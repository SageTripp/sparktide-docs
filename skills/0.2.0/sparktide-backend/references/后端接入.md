# 后端接入

后端 SDK 跑在现有 Java 或 Kotlin 业务进程里。它扫描类型化声明、向平台注册能力、挂上 `/api/ai`，并在工具回调时走回原来的认证链。会话和执行记录在平台。业务服务继续判断数据权限。

下面的类是说明性片段。设备数据不要照搬。文档仓库里可编译的示例见 完整示例（配套文档：/0.2.0/开发接入/完整示例.md）。

## 1. 添加依赖

先按 接入总览（配套文档：/0.2.0/开发接入/接入总览.md） 把同一版本安装到本机 Maven 仓库。Java 17 应用：

::: code-group

```kotlin [Gradle Kotlin DSL]

    mavenCentral()
    mavenLocal()
}

dependencies {
    implementation("dev.sparktide:sdk-spring-boot-starter:0.2.0")
    implementation("dev.sparktide:sdk-model-openai-compatible:0.2.0")
    implementation("org.springframework.boot:spring-boot-starter-web")
}
```

```groovy [Gradle Groovy DSL]

```


Java 8 / Spring Boot 2.6.6 把 `sdk-spring-boot-starter` 换成 `sdk-spring-boot2-starter`。该 Starter 传递 `sdk-java8`，字节码目标是 Java 8。同一进程不要同时依赖 `sdk-java` 和 `sdk-java8`。供应商模块版本与 Starter 相同。DeepSeek 改用 `sdk-model-deepseek`，模型类继承 `DeepSeekProvider.Model`。官方 OpenAI 用 `sdk-model-openai`，Ollama 用 `sdk-model-ollama`。

构建 SDK 仓库本身用 JDK 17。消费 Boot 2 Starter 的业务进程可以运行在 JDK 8。

## 2. 声明连接、模型和智能体

`@AiProvider` 放在 Provider 类型上，保存协议地址和密钥来源。`baseUrl` 与 `endpoint` 互斥：`baseUrl` 是协议根，例如供应商的 `/v1`，SDK 再拼接路径；`endpoint` 是完整请求地址，SDK 原样使用。`apiKey`、`apiKeyEnv` 和子类里的程序化密钥只能留一种。`${...}` 在每次调用时读取宿主配置。密钥不进入注册图。

`@AiModel` 只写供应商模型名和能力。`provider` 必须指向带配置的 Provider 类。Java 静态嵌套 `Model` 不会自动绑到外层子类，所以要显式写 `provider`。`toolCalling`、`streaming`、`structuredOutput` 默认 `UNKNOWN`。`UNKNOWN` 表示尚未验证，不能把它写成已支持。确认供应商行为后再标 `SUPPORTED` 或 `UNSUPPORTED`。

`@Agent` 放在普通类上，不需要 `@Component`。`name` 以小写字母开头，可含数字和连字符，最长 64。`model` 第一项是主模型，其余是显式候选，不能重复。`tools` 和 `knowledge` 只暴露这些 Bean 上标注过的方法。`defaultAgent = true` 的智能体在一个应用里最多一个。

::: code-group

```java [Java]
@AiProvider(baseUrl = "${OPS_MODEL_BASE_URL}", apiKey = "${OPS_MODEL_API_KEY}")
public class BusinessProvider extends OpenAICompatibleProvider {}

@AiModel(
    name = "business-model",
    model = "example-chat-model",
    provider = BusinessProvider.class,
    maxOutputTokens = 1024)
public final class BusinessModel extends BusinessProvider.Model {
    public BusinessModel() {}
}

@Agent(
    name = "main",
    instructions = "设备状态以工具结果为准，处置建议引用手册。",
    model = {BusinessModel.class},
    tools = {EquipmentStatusTool.class},
    knowledge = {RunbookKnowledge.class},
    defaultAgent = true)
public final class OpsAssistant {}
```

```kotlin [Kotlin]
@AiProvider(baseUrl = "\${OPS_MODEL_BASE_URL}", apiKey = "\${OPS_MODEL_API_KEY}")
class BusinessProvider : OpenAICompatibleProvider()

@AiModel(
    name = "business-model",
    model = "example-chat-model",
    provider = BusinessProvider::class,
    maxOutputTokens = 1024)
class BusinessModel : OpenAICompatibleProvider.Model()

@Agent(
    name = "main",
    instructions = "设备状态以工具结果为准，处置建议引用手册。",
    model = [BusinessModel::class],
    tools = [EquipmentStatusTool::class],
    knowledge = [RunbookKnowledge::class],
    defaultAgent = true)
class OpsAssistant
```

:::

`example-chat-model` 要换成供应商真实的模型标识。这个字段不解析配置占位符。

`@Agent` 还有运行额度：`maxSteps` 默认 8，允许 `-1` 或 `1..32`；`maxToolCalls` 默认 8，允许 `-1`、`0` 或 `1..64`；`timeoutSeconds` 默认 60；`maxBudgetUnits` 默认 32000，范围 `256..1000000`，统计的是序列化字符预算，不是供应商账单 Token。`-1` 要求平台接受同一合同。`commonComponents` 默认 `true`，允许前端注册 SDK 通用展示组件；前端未注册则不会显示。

DeepSeek 的写法。Kotlin 字符串里的 `${` 要写成 `\${`，否则会变成模板：

::: code-group

```java [Java]
@AiProvider(apiKey = "${business.ai.deepseek.api-key}")
public class BusinessDeepSeekProvider extends DeepSeekProvider {}

@AiModel(model = "deepseek-flash", provider = BusinessDeepSeekProvider.class,
    streaming = Support.SUPPORTED, toolCalling = Support.SUPPORTED)
public class BusinessModel extends BusinessDeepSeekProvider.Model {}
```

```kotlin [Kotlin]
@AiProvider(apiKey = "\${business.ai.deepseek.api-key}")
class BusinessDeepSeekProvider : DeepSeekProvider()

@AiModel(model = "deepseek-flash", provider = BusinessDeepSeekProvider::class,
    streaming = Support.SUPPORTED, toolCalling = Support.SUPPORTED)
class BusinessModel : DeepSeekProvider.Model()
```

:::

`DeepSeekProvider` 默认地址是 `https://api.deepseek.com`。适配器把统一的 `max_completion_tokens` 转为 DeepSeek 的 `max_tokens`，并发送非思考参数。当前平台消息协议不保留跨轮推理内容，打开思考模式会在创建适配器时失败。

## 3. 把业务方法标成工具或知识

工具和知识是 Spring Bean。只有被某个 `@Agent` 的类型引用点名的方法才会暴露。输入输出使用 Java `record`、受约束 POJO 或 Kotlin `data class`，SDK 生成闭合 Schema。

::: code-group

```java [Java]
@Component
public class EquipmentStatusTool {
    public record Input(String equipmentId) {}
    public record Output(String equipmentId, String state) {}

    @Tool(name = "equipment-status", description = "查询机组当前状态，只读")
    public Output execute(Input input, ToolContext context) {
        return equipmentService.status(input.equipmentId());
    }
}
```

```kotlin [Kotlin]
@Component
class EquipmentStatusTool {
    data class Input(val equipmentId: String)
    data class Output(val equipmentId: String, val state: String)

    @Tool(name = "equipment-status", description = "查询机组当前状态，只读")
    fun execute(input: Input, context: ToolContext): Output =
        equipmentService.status(input.equipmentId)
}
```

:::

写操作把 `confirmation` 设为 `Confirmation.REQUIRED`，并用 `context.callId()` 做业务幂等。同一 `callId` 的重放不能产生第二次副作用。SDK 的调用账本负责投递幂等，业务事务仍要自己认这个键。

::: code-group

```java [Java]
@Tool(name = "restart-service",
      description = "重启机组服务，执行前需要用户确认",
      confirmation = Confirmation.REQUIRED,
      effect = AgentTool.Effect.DANGEROUS)
public Output execute(Input input, ToolContext context) {
    return equipmentService.restart(input.equipmentId(), context.callId());
}
```

```kotlin [Kotlin]
@Tool(name = "restart-service",
    description = "重启机组服务，执行前需要用户确认",
    confirmation = Confirmation.REQUIRED,
    effect = AgentTool.Effect.DANGEROUS)
fun execute(input: Input, context: ToolContext): Output =
    equipmentService.restart(input.equipmentId, context.callId())
```

:::

知识方法接收 `KnowledgeQuery` 和 `KnowledgeContext`，返回 `KnowledgeResult`。按 `context.tenantId()` 和 `context.userId()` 过滤；过滤发生在业务查询里。

::: code-group

```java [Java]
@Knowledge(name = "ops-runbook", description = "当前租户可见的运维手册", topK = 3)
public KnowledgeResult retrieve(KnowledgeQuery query, KnowledgeContext context) {
    return runbooks.search(context.tenantId(), query.query(), query.topK());
}
```

```kotlin [Kotlin]
@Knowledge(name = "ops-runbook", description = "当前租户可见的运维手册", topK = 3)
fun retrieve(query: KnowledgeQuery, context: KnowledgeContext): KnowledgeResult =
    runbooks.search(context.tenantId(), query.query(), query.topK())
```

:::

需要展示卡片时，在成功结果上加 `@RenderWith("组件标识", version = "1.0.0")`。前端用相同标识注册 Renderer。后台不复制一份界面目录。

类级别的 `@AgentTool` / `@AgentKnowledge` 仍可用于已有的整类适配。新代码优先使用方法注解，并由 `@Agent(tools = ...)` 引用 Bean 类型。

## 4. 写连接配置

出现 `sparktide.application` 后，自动配置会打开平台注册和聊天入口，并把声明所有者设为这个应用标识。生产模式默认 `VERIFY`：启动时要求这些定义已经发布。`DEVELOPMENT` 才会自动同步并允许启动发布。

```yaml
sparktide:
  application: ${SPARKTIDE_APP_ID:ops-assistant}
  platform:
    url: ${SPARKTIDE_PLATFORM_URL:http://127.0.0.1:18092}
    credential: ${SPARKTIDE_TOKEN:}
  callbacks:
    url: ${SPARKTIDE_PUBLIC_BASE_URL:http://127.0.0.1:8089}
    credential: ${SPARKTIDE_CALLBACK_TOKEN:}
    secret-reference: ${SPARKTIDE_CALLBACK_SECRET_REF:OPS_CALLBACK_TOKEN}
    ledger-directory: ${SPARKTIDE_LEDGER_DIR:./data/ledger}
    port: ${OPS_CALLBACK_PORT:8089}
  bind-address: ${OPS_CALLBACK_BIND:127.0.0.1}
  deployment:
    mode: ${OPS_DEPLOYMENT_MODE:PRODUCTION}
    version: 1.0.0
  http:
    path: /api/ai
```

| 键 | 作用 |
| --- | --- |
| `sparktide.application` | 已登记的应用标识。它打开 SDK，也是声明所有者 |
| `sparktide.platform.url` | 平台根地址 |
| `sparktide.platform.credential` | 应用注册、核验和续租凭据。只放在后台 |
| `sparktide.callbacks.url` | 平台能够访问到的回调根地址 |
| `sparktide.callbacks.credential` | 回调认证凭据，与平台侧引用配对 |
| `sparktide.callbacks.secret-reference` | 平台保存的回调凭据引用名 |
| `sparktide.callbacks.ledger-directory` | 工具幂等账本目录。有工具回调时必填 |
| `sparktide.callbacks.port` | 回调监听端口，默认 8089 |
| `sparktide.bind-address` | 回调绑定地址，默认 `127.0.0.1` |
| `sparktide.deployment.mode` | `PRODUCTION` 或 `DEVELOPMENT` |
| `sparktide.deployment.version` | 声明版本，缺省 `1.0.0`。已发布定义变化时递增 |
| `sparktide.http.path` | 聊天路由前缀，默认 `/api/ai` |

同一含义如果同时写了新旧键且值不同，启动会拒绝。诊断日志只保留键名，不打印凭据值。聊天开启后，若未配置请求头上限，SDK 把最大请求头设为 32KB；自行配置时至少 16KB，以便容纳认证转发。

跨源浏览器在 `sparktide.chat.security.allowed-origins` 列出完整 origin，不含路径和通配符。只有跨源 Cookie 才把 `allow-credentials` 设为 `true`，并继续使用业务已有的 CSRF。同源部署保持默认。

## 5. 发布与生产启动

开发：

1. 设置 `OPS_DEPLOYMENT_MODE=DEVELOPMENT` 后启动。该模式使用 `REGISTER`，未发布的声明会在启动路径同步。
2. 注入 `SparkTideRegistration`，阅读 `registrationReport()`。报告里的冲突或已撤销版本需要先处理。
3. 需要单独发布时调用 `registration.release("变更说明")`。返回的是发布结果，不是聊天是否成功。

生产：

1. 保持 `deployment.mode: PRODUCTION`。此时启动策略是 `VERIFY`，`sparktide.publish=true` 会被拒绝。
2. 生产进程要求代码声明已经发布，且默认入口与平台一致，否则启动失败。
3. 变更定义时提高 `sparktide.deployment.version`，由受控作业调用 `release`。普通线上实例不在启动时创建新版本。
4. `capabilitiesReady()` 仅在注册开启、声明全部已发布且续租正常时为真。`lastLeaseFailure()` 给出脱敏的续租失败说明。

回调端口必须能被平台访问。默认绑定本机回环地址，只适合平台和业务在同一台机器。分开部署时修改 `bind-address`，并让 `callbacks.url` 指向平台实际能请求的地址。

## 6. 可选模块

| 模块 | 何时加入 | 边界 |
| --- | --- | --- |
| `sdk-document-pdf` | 业务工具要生成 PDF | 传递 `sdk-document-spi`。业务实现 `DocumentStorage`，自行配置有使用权的 TrueType 字体。SDK 不抓取任意网址。Word、Excel、PPT 不在该模块 |
| `sdk-query-graphql` | Java 17 业务要把只读 GraphQL 查询做成工具 | 依赖 GraphQL Java `26.0`。业务提供只读 schema 和同步 resolver。它不提供智能体循环、数据库连接或另一套身份 |
| `sdk-kotlin` | 需要协程等待或 Kotlin DSL | 仅用于 Java 17 / `sdk-java` 线，不能与 `sdk-java8` 或 Boot 2 启动器混用。挂起工具、权限和 `chatAs` 在文档仓库 `examples/0.2.0/kotlin-ops-assistant` |

PDF 工具返回 `DocumentResult`，文件字节由业务存储保存。前端若要预览业务文件，按 自定义界面（配套文档：/0.2.0/开发接入/自定义界面.md） 提供下载和预览回调。平台托管 PDF 走聊天入口里的成果下载，见 HTTP 接入（配套文档：/0.2.0/开发接入/HTTP接入.md）。

## 7. 启动后检查

1. 业务进程日志里没有凭据原文。`SparkTideProperties` 的诊断文本固定为 `credentials=REDACTED`。
2. 开发模式的 `registrationReport()` 没有未解决冲突。
3. 用现有登录调用 `POST /api/ai/chat`，或按 前端接入（配套文档：/0.2.0/开发接入/前端接入.md） 打开页面。应用凭据不出现在浏览器。
4. 工具被调用时，业务 Service 仍能读到原来的登录主体。映射规则见 [身份与权限](身份与权限.md)。

注解参数、配置字段和错误码按依赖列在 SDK 依赖（配套文档：/0.2.0/参考资料/SDK依赖/README.md）。后端 SDK（配套文档：/0.2.0/参考资料/后端SDK.md） 仍是这些章节的入口。
