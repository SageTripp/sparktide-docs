# 启澜问题排查

本 Skill 对应 **0.2.0**。先取得不含密钥与业务正文的最小诊断信息：失败入口、HTTP 状态、`error.code`、关联标识、运行/任务阶段、平台与 SDK 版本。不要要求整个请求头、完整 token 或无关业务数据。

## 定位失败层

| 现象 | 先查 |
| --- | --- |
| 前端 `status === 0` | 本地客户端生命周期、登录配置、网络；不要当作平台 HTTP 错误 |
| `/api/ai` 返回失败 | 业务登录、主体映射、SDK 网关；平台错误消息可能被脱敏 |
| 平台 HTTP 失败 | 认证/范围、输入、修订、容量，再查具体 `error.code` |
| HTTP 202 后任务失败 | 读取运行或任务终态、事件和领域错误，而非只重发原创建请求 |
| SSE 断开但后台继续 | 网络流和运行生命周期分开，断流不取消运行 |

按 code 在[公共错误码](references/公共错误码.md)中定位条目，不必把整份索引读入上下文；再查[能力与限制](references/能力与限制.md)确认入口是否开放。合同、方法或 SDK 组件存在，不能证明当前部署启用。

## 常见判断

- 401：恢复真实登录，检查失效/吊销；不要换成平台管理凭据代替用户。
- 403：核对应用、主体、租户及数据权限；不通过更改 appId 或 context 绕过。
- 409 / 412：先读当前对象、修订和原幂等意图，明确是否重新提交；不自动覆盖。
- 429 / 503：分清限流、容量或依赖故障。遵守服务端等待提示；写入先核对是否受理。
- `COMMIT_OUTCOME_UNKNOWN`、`TOOL_OUTCOME_UNKNOWN`、`EMBEDDING_OUTCOME_UNKNOWN`：核对原操作、业务侧记录或计费回执，不自动重放，不换幂等键掩盖未知结果。
- SSE 游标问题：区分可靠事件与临时预览。根据当前运行状态和 SDK 恢复策略继续，不把未知尾部拼成已确认结果；不跳过可靠序号。
- 工具/知识失败：检查业务登录回调、授权、输入输出契约和依赖的已发布版本，不能通过放宽权限或更换用户修复。

诊断阶段默认读状态与配置，修复范围按用户授权执行。删除运行数据、初始化数据库、重新发布资源或切换服务并不是读取错误码所附带的权限。避免无限循环重试，拿到新的可核对证据后再决定下一步。

交付原因、修改与验证层级。缺少实际服务时明确只能验证到静态配置或编译；不能把 HTTP 200、日志中没有异常或页面演示当作完整业务成功。
