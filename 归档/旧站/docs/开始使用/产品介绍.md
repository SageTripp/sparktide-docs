# 认识启澜

**SparkTide · 启澜是部署在自有基础设施中的智能体平台。** 它把模型、业务工具、知识和执行过程组织起来，让你在现有产品里提供可持续对话、可调用业务能力的助手。

业务系统保留登录、授权、数据权限和事务。启澜提供平台服务与前后端 SDK，不要求用户离开原产品，也不要求为 AI 再维护一套业务系统。

## 它在系统中的位置

```text
你的产品界面
  └─ 前端 SDK：聊天、会话、流式状态、确认与业务卡片
       └─ 你的业务后端：原有登录、权限、Service 与数据
            └─ 后台 SDK：声明能力、适配身份、连接与回调
                 └─ 启澜平台：资源版本、会话、运行与事件
                      └─ 模型服务 / 已授权的工具与知识
```

推荐调用链路是 **浏览器 → 业务后端 → 平台服务**。平台管理凭据和模型密钥只在服务端使用，不交给浏览器。

## 产品组成

| 组成 | 你用它完成什么 | 主要使用者 |
| --- | --- | --- |
| 平台服务 | 管理应用与资源版本，保存会话，执行运行并提供事件流 | 平台运维、业务服务 |
| 后台 SDK | 声明模型、智能体、工具与知识，接入业务身份与调用 | Java / Kotlin 开发者 |
| 前端 SDK | 接入聊天面板，或用统一状态层构建自己的界面 | JS / TS、React / Vue 开发者 |
| 管理控制台 | 检查资源与运行、维护授权、处理故障和追溯变更 | 平台管理员、应用管理员 |

SDK 的语言、框架和 API 支持随版本变化。公开 **0.1.0** 与内部开发候选采用不同的接入 API；开始写代码前先看[版本与获取](版本与获取.md)。

## 业务接入与平台管理

日常开发从业务代码开始：声明助手的职责，连接一个模型，再按需要开放工具或知识。SDK 管理的资源可在控制台查看，**不必先在控制台重复建一套定义**。

平台管理员负责应用范围、初始凭据和平台授权；业务团队负责原有用户身份、数据访问和工具副作用。控制台用于管理与诊断，不是用户使用助手的必经入口。

## 核心对象

先认识五个对象，就能跟上后续教程：

| 对象 | 可以怎样理解 |
| --- | --- |
| 应用 | 一个业务产品的资源与权限范围 |
| 智能体 | 助手的职责、模型与允许使用的能力，按版本管理 |
| 会话 | 用户与智能体的一组连续消息 |
| 运行 | 一次消息触发的执行过程，可追踪状态、调用与结果 |
| 资源版本 | 智能体依赖的模型、工具、知识或界面定义版本 |

## 从对话到业务能力

- **回答问题**：先连接模型并跑通一轮对话，再验证追问与历史恢复。
- **查询或操作业务**：把已有 Service 暴露为工具，继续执行原授权与数据权限。
- **利用内部资料**：接入知识来源，在回答中展示引用，并按权限预览来源。
- **展示业务结果**：按需将工具结果渲染为前端卡片，保留文字回退。

能力支持范围和限制见[能力状态](../产品支持/能力状态.md)。部署成功或代码编译通过，不等于模型实网、业务权限或生产容量已经验收。
