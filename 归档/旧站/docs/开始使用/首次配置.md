# 首次应用配置

先创建应用，再将 SDK 引入业务项目。可以在控制台创建应用，也可以使用 [快速开始](快速开始.md) 中的受控初始化作业；已有应用不必重复创建。后台 SDK 管理业务资源，控制台提供配置维护与运行排查。

平台启动后，使用管理员凭据打开 `/console/index.html`。页面内存保存本次连接凭据，刷新或关闭页面后重新连接。

## 配置顺序

![从部署到业务上线](/images/使用路径.svg)

先确定应用，再配置模型链路，然后组合业务能力，最后发布默认智能体并接入用户身份。控制台与 SDK 调用同一套 API，资源可以查看和治理；代码管理的资源显示来源且不可人工修订。

## 控制台入口

| 入口 | 常用操作 |
| --- | --- |
| 总览 | 查看全部应用状态，选择应用后查看运行和告警 |
| 应用管理 | 查找应用，进入应用配置、运行记录与设置 |
| 应用配置 | 维护 SDK 与平台资源、访问凭据、配额和发布版本 |
| 运行记录 | 查询当前应用的运行、调用链、模型与工具记录 |
| 告警 / 操作记录 | 处理当前应用的问题，追溯配置变更 |
| 平台设置 | 管理共享模型、服务状态、数据保留与脱敏 |

首次登录默认进入总览，点击应用选择器旁的“创建应用”。创建后自动选中新应用并进入应用配置，依次准备凭据、接入 SDK、配置资源并验证发布。后续选择应用时回到该应用总览。

配置顺序可参考本文及[应用接入教程](../教程/README.md)。SDK 管理的定义在业务代码中修改，平台管理的草稿在控制台维护。

帮助中心提供操作步骤和问题处理方法。完整说明见[控制台手册](../使用指南/控制台/README.md)。

## 资源编辑与版本

1. 在列表中搜索标识或描述，按草稿、已发布、已撤销筛选。
2. 点击“新建”填写资源标识和三段版本号，例如 `1.0.0`。
3. 先保存草稿，再发布。依赖项必须先发布。
4. 已发布版本不可原地修改；用“复制为新版本”建立新配置。
5. 需要撤销时先查看使用该资源的智能体，避免现有入口失去依赖。

相同标识可以存在多个精确版本。`1.0.1` 不会自动替代所有引用 `1.0.0` 的智能体。默认入口切换影响之后的新任务，运行中的计划固定原版本。

## 使用高级配置

常见字段通过表单填写。工具 Schema、智能体允许列表、预算、流式选项和定价等可在“高级配置 · 完整 JSON”编辑。

修改 JSON 后，本次保存以 JSON 为准；普通配置暂停编辑。“放弃 JSON 修改，返回表单”恢复切换前输入。错误内容保留在当前抽屉，修改后再次保存。关闭抽屉前请保存需要保留的改动。

托管知识“复制为新版本”只复制资源定义，不复制该版本已经导入的文档。新版本需要重新导入文档后发布。

## 首次配置完成的判断

- 概览存在已发布的默认智能体。
- 使用业务用户身份发起任务，收到回答和终态。
- 若启用工具，业务服务收到正确应用、用户和租户上下文。
- 若启用知识，前端能展示引用；若启用 UI，客户端已注册对应组件版本。
