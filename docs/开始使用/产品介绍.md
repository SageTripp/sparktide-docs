# 初识 SparkTide

SparkTide 是部署在自己基础设施中的智能体底座。把现有模型、业务接口和知识接进来，再用聊天 SDK 嵌入自己的网页，就能提供能查询业务、引用资料和请求操作确认的助手。

## 一个使用场景

用户在设备管理页面问“pump-01 是否正常，该怎么巡检”。前端聊天 SDK 把消息交给业务后台；后台识别已登录用户；底座选定智能体和模型，调用后台已登记的设备工具与知识 Provider，最后将回答和引用通过事件流返回。

无需为这一轮对话另建会话数据库、手写事件解析或让浏览器持有模型密钥。真实设备权限和查询逻辑继续由业务系统负责。

## 两套独立 SDK 与底座

| 部分 | 负责什么 | 你需要准备什么 |
| --- | --- | --- |
| 业务后台 SDK（Java / Kotlin、Spring） | 接入工具、知识和业务权限；声明模型与智能体；提供标准聊天 HTTP API 和身份适配 | 业务能力、现有登录身份、部署参数 |
| 前端聊天 SDK（JS / TS、React / Vue） | 调用业务后台；封装会话、流式事件、状态与 ChatPanel | 业务 API 地址、业务登录认证、页面样式 |
| 底座 | 保存会话、消息和 Run，执行模型 / 工具循环、审批、权限检查与事件协议 | 数据库、模型出站策略与执行侧密钥 |

浏览器 → 业务后台 → 底座，是推荐链路。后台承担业务接入与 HTTP 适配，核心会话和执行能力由底座统一管理；两套 SDK 不重复实现这些能力。

## 先认识三个概念

**应用**是一个业务产品的隔离范围，例如设备运维系统。**智能体**是一份固定版本的提示词、模型配置与能力允许列表。**会话**包含多轮消息；每次发送会产生一个 **Run**，事件流展示该 Run 的进度和结果。

模型有“提供商 → 模型 → 应用绑定 → 配置”这条声明链，第 3 步会结合代码解释。此处先知道它让连接、应用授权和调用策略能独立版本化即可。
