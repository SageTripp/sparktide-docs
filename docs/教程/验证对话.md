# 5. 验证第一轮对话

**开始前：** 聊天页面已连接。**本步目标：** 确认真实模型、业务后台与前端 SDK 的完整链路，而不只是看到网页。

## 1. 发出第一条消息

输入“你好，请用一句话介绍你能做什么”，点击发送。

应看见你的消息、助手回复与 `SUCCEEDED` 终态。这里还没接设备、订单或知识，助手只能依据提示词和模型能力回答；不要用业务查询来判断本步骤是否完成。

如果你选择了真正的模型供应商，本步骤会使用该服务并产生对应请求。仅使用本地兼容替身时，只能证明接入链路，不能证明供应商实网可用性。

## 2. 确认会话可以续接

1. 在当前会话追问“把刚才的回答再缩短一点”，应追加在同一会话中。
2. 给会话改名，列表显示新标题。
3. 刷新网页，重新输入本地业务令牌并连接，从列表选择原会话，应能读到历史。
4. 点击“新会话”再发送，得到新的会话。

历史目前返回最近最多 20 条消息。刷新和断开订阅不会自动取消后台运行；需要停止时明确点击取消。删除活动运行所在会话可能返回 409，需要先取消并等到终态。

## 3. 查看请求是如何流动的

浏览器开发工具 Network 中应看到 `/api/ai/conversations`、`/api/ai/chat`、`/api/ai/runs/.../events` 等业务接口。**不会直接请求底座 `/v1/apps/...`。**

一次发送创建一个 Run，返回 conversationId。事件流负责增量展示；状态和历史由底座保存。无需先调用 createConversation 才能发第一条消息。

## 出错时按这一顺序查

| 现象 | 先检查什么 | 进一步阅读 |
| --- | --- | --- |
| 页面打不开 | Vite 终端是否启动，5173 是否空闲 | [接入聊天页面](接入前端.md) |
| /api/ai 返回 404 或代理失败 | 后台是否在 8091，chat.enabled=true，代理是否生效 | [后台步骤](接入后台.md) |
| 401 / 403 | 填的是 browser-token.txt；后台 USER 是否过期、属于 tutorial | [创建开发身份](创建应用.md) |
| 缺少默认智能体或版本未发布 | 清单启动预检是否通过，默认入口 main/1.0.0 是否设置 | [声明与发布](../开发接入/业务接入/声明式注册与启动发布.md) |
| 模型连接被拒或密钥不可用 | 实际 endpoint 的 origin、secretRef 名称和应用授权一致 | [环境变量](../部署运维/环境变量.md) |
| Run 失败 / 超时 | 后台与底座错误码，模型服务返回及能力兼容性 | [模型能力](../开发接入/模型治理/模型能力声明与检查.md) |
| 收到 429 或 410 | 并发名额 / 事件保留窗口，先查询权威 Run 状态 | [会话与运行](../使用指南/运行与审计.md) |

浏览器收到错误后不要自动重发聊天写请求。保留 Run ID 或使用稳定幂等键定位已有结果；只恢复事件订阅不会再创建一轮聊天。

## 检查点与下一步

完成“回答成功、同会话追问、刷新历史”三项后，基础接入已经完成。现在可以把教程代码接入现有项目，或下一步增加工具和知识。

需要模型切换、UI 卡片或更多知识能力时，从[能力指南](../使用指南/README.md)选一条需求路径；无需先读完所有专题或 API。
