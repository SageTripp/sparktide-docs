# 独立运行与数据库配置

不使用容器时，可以直接运行平台 Jar。适合已有 JVM 服务发布体系或受控的内部服务器。

## 构建制品

```powershell
.\gradlew.bat clean build
New-Item -ItemType Directory -Path releases/0.1.0 -Force
Copy-Item server-spring/build/libs/server-spring-0.1.0-SNAPSHOT.jar releases/0.1.0/platform.jar
```

不要直接在运行中的 `build/libs` 制品上反复构建。将 Jar、运行目录和服务管理配置分开，保留上一版本与对应数据库备份。

## 配置并启动

在服务账户的环境中设置数据库、管理员凭据和密钥。下面的口令变量应由部署系统预先注入：

```powershell
$env:SPARKTIDE_DB_URL = 'jdbc:postgresql://db.internal:5432/sparktide'
$env:SPARKTIDE_DB_USER = 'sparktide'
$env:SPARKTIDE_BIND = '127.0.0.1'
$env:PORT = '8080'
$env:SPARKTIDE_ALLOWED_ORIGINS = 'https://model.example.com'
$env:SPARKTIDE_SECRET_NAMES = 'MODEL_API_KEY'
$env:SPARKTIDE_SECRET_ORIGINS = 'MODEL_API_KEY=https://model.example.com'
# 预先注入 SPARKTIDE_ADMIN_TOKEN、SPARKTIDE_DB_PASSWORD、MODEL_API_KEY。
java -jar releases/0.1.0/platform.jar
```

Linux 服务管理器使用相同变量。固定工作目录、非 root 账户、重启策略、停止超时和日志轮转。默认只绑定回环地址；容器或内网网关连接时显式设置可达地址。

## 数据库

生产环境使用 PostgreSQL，默认连接池上限为 12。数据库账户需要执行当前 Flyway 迁移所需的权限；首次启动会自动执行 V1–V6 迁移。

未设置 DB_URL 时，平台使用相对工作目录中的 H2 文件 `./data/sparktide`。它适合本机开发，不应误当作生产 PostgreSQL。更换进程工作目录会使用另一个文件位置，看起来可能像“数据丢失”。

生产数据库的连接加密、凭据托管、备份保留与审计由部署环境统一配置。禁止手改已经执行过的迁移脚本。

## 停止与升级

先停止新请求，等待运行任务结束，再停止服务并替换制品。重启会明确终结未完成任务，不自动重放工具调用。完整流程见[升级与备份](./升级与备份.md)。
