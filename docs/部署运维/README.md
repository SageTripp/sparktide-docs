# 部署底座与上线

启澜平台部署在你的基础设施中。这里帮助你准备可靠的运行环境，并在升级、故障和恢复时找到正确步骤。

**只是第一次体验？** 从[教程的环境准备](../教程/准备环境.md)启动公开 0.1.0 示例，健康检查通过后回到[创建应用](../教程/创建应用.md)。不要把开发环境的身份和凭据配置直接带到生产。

## 选择部署方式

| 方式 | 适合什么情况 | 指南 |
| --- | --- | --- |
| Docker | 已有容器部署流程，需要固定镜像版本 | [Docker 部署](Docker部署.md) |
| 独立 Jar | 由现有 Java 服务运维流程管理进程 | [独立部署](独立部署.md) |
| 多实例 | 需要共享数据库与任务协调，已具备集群运维能力 | [集群部署](集群部署.md) |

先核对[版本与获取](../开始使用/版本与获取.md)。公开镜像与 Jar 为 **0.1.0**；内部候选 SDK 所需的平台由维护者配套提供，不能把旧制品当作新 API 的运行环境。

## 首次上线的顺序

### 1. 准备持久化与配置

按所选部署指南配置数据库和数据目录，检查[环境变量](环境变量.md)。使用固定制品版本，明确配置与秘密的注入来源，并准备[备份和恢复](升级与备份.md)方案。

### 2. 打通安全调用链

按[HTTPS 与网关](HTTPS与网关.md)配置业务入口和平台连接，验证 SSE 不被缓冲或意外中断。按应用准备平台接入、回调和出站授权。

浏览器登录、应用管理、回调和平台初始化凭据用途不同，不能互相代替。模型密钥只在相应的服务端配置或密钥设施中使用，不放进前端代码。

### 3. 对照业务验收

确认业务系统使用配套双 SDK，沿用原认证与数据权限。开发同步草稿和生产核验发布分开执行；不要在生产启动过程中悄悄覆盖已经发布的定义。

验收清单见[接入规划](../开发接入/接入流程.md#平台与验收)。健康检查只能说明服务状态，不能替代实际对话、权限、模型和业务调用验证。

### 4. 建立运行证据

用真实 Run 检查状态、调用链和结果，准备[监控与排障](监控与排障.md)、[可观测性与调用链](可观测性与调用链.md)，确认告警和恢复责任。

## 日常维护

| 当前任务 | 阅读入口 | 应得到的结果 |
| --- | --- | --- |
| 排查对话或任务失败 | [监控与排障](监控与排障.md) → [调用链](可观测性与调用链.md) | 从实际 Run 与调用记录定位原因 |
| 升级、迁移或回退 | [升级与备份](升级与备份.md) | 明确兼容边界，备份可恢复 |
| 管理应用与资源 | [控制台手册](../使用指南/控制台/README.md) | 在授权范围内维护资源与查看运行 |
| 核对执行和治理结果 | [运行治理与执行核对](运行治理与执行核对.md) | 输出受当前权限约束，结论有证据 |
| 导出审计与配置留存 | [审计查询、导出与留存](../开发接入/运维治理/审计查询导出与留存.md) | 留存、访问和清理策略明确 |

## 上线前最后检查

- [ ] 平台与双 SDK 版本配套，固定制品与校验值已记录。
- [ ] 数据持久化、备份与恢复路径可用。
- [ ] HTTPS、SSE、回调和出站授权已验证。
- [ ] 登录、撤销、跨主体和数据权限有实际验收记录。
- [ ] 发布、回退、告警和故障处理有明确责任人。
- [ ] 生产容量与模型供应商限制已单独验证，没有用构建成功替代验收。
