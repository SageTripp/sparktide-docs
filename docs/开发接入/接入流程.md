# 接入已有系统

目标不是另建一个独立聊天系统，而是让用户在原产品中调用业务能力。**保留已有登录、Service、数据权限和事务；用后台 SDK 连接平台，用前端 SDK 接入界面。**

## 开始前确认三件事

1. **版本是否配套。** 本路线使用后台候选 `0.1.1-auth.20261023-6`、同轮前端候选 tgz，以及支持 `business-auth/1.0` 的平台。它们尚未公开发行；只有公开包时请走 [0.1.0 固定教程](../教程/README.md)。
2. **业务身份从哪里来。** 确认现有 Bearer、Cookie/CSRF 或自定义认证头，以及用户、租户和权限在原系统中的来源。
3. **平台由谁维护。** 确认平台地址、应用范围、接入与回调凭据、模型出站要求。不要把这些管理材料交给浏览器。

完整代码与配置见 [SDK 接入步骤](SDK简化接入.md)。本页用于分配工作和确定交付顺序。

## 最短接入闭环

| 顺序 | 交付内容 | 完成标志 |
| --- | --- | --- |
| 1. 准备连接 | 配套 SDK、平台地址、应用与授权、模型配置 | 后台能连接目标平台，凭据只留在服务端 |
| 2. 接入后台 | Provider、Model、Agent 声明与原业务认证 | 原登录用户能访问业务聊天入口 |
| 3. 嵌入界面 | 一个客户端和聊天面板 | 能发送消息、接收流式响应并恢复历史 |
| 4. 开放业务能力 | 一个已有 Service 的工具或知识入口 | 数据仍受原用户、租户和业务权限约束 |
| 5. 联合验收 | 身份切换、失败恢复、取消与发布检查 | 不串会话、不泄露凭据、不误报业务执行结果 |

先跑通对话，再增加业务工具和 UI 卡片。不要在第一步同时实现全部扩展能力。

## 后台团队

- 选择匹配 Java / Spring Boot 的 Starter 和需要的模型适配器。
- 用 `@AiProvider` 声明连接，用 `@AiModel` 声明模型能力，用 `@Agent` 组织助手职责及能力引用。
- 工具和知识 Bean 调用原业务 Service。原认证已提供 Principal 时默认复用其 name；自定义用户或租户结构只需按需提供 `BusinessPrincipalMapper` 字段映射。
- 在 YAML 配置平台、应用与回调连接及部署信息。SDK 处理注册、回调、原认证链重入、Origin/CORS 和认证上下文清理。

**交给前端的内容**：业务 API 前缀、原登录方式、CSRF 要求、允许来源和智能体名。**不交给前端的内容**：模型密钥、平台管理凭据、回调秘密和内部认证胶囊。

入口权限可以声明在 Agent 上；数据权限仍由业务 Service 判断。无需为 AI 复制角色查询、scope/read 层或业务授权协议。详见[后台 SDK](业务后台SDK.md)。

## 前端团队

- 用 `createClient` 创建一个客户端，`baseUrl` 指向业务后台，`auth` 复用原有登录。
- `identityKey` 使用非秘密的主体、租户或登录代次；注销为 `null`，普通 token 续期保持不变。
- React / Vue 3 / Vue 2 使用对应聊天面板；自定义界面复用同一 ChatStore、hook 或 Vue 2 mixin。
- 普通 `context` 只放发送时的业务数据快照。业务筛选项继续读取公共业务 API，不在 context、卡片 props 或日志中传认证值。

客户端管理事件、引用、历史和迟到响应。**关闭页面、断开连接或 reset 不等于取消后台运行**；用户明确停止时才请求取消。详见[前端 SDK](前端SDK.md)与[框架接入](React与Vue.md)。

## 平台与验收

平台团队准备应用授权、模型与回调出站策略、密钥、数据库、HTTPS/SSE 和备份。开发环境同步草稿，生产环境核验已经发布的定义；发布作业独立执行。

联合验收至少覆盖：

- [ ] 原有登录用户可以对话，并能恢复自己的历史。
- [ ] 工具与知识沿用原业务授权，跨主体、跨租户访问被拒绝。
- [ ] 注销、撤销与过期后，不继续使用旧身份执行回调或展示迟到结果。
- [ ] 来源预览重新校验权限，认证材料不进入事件、模型、历史或日志。
- [ ] 重复提交、写操作重试和取消行为符合业务幂等与事务要求。
- [ ] 已分别记录模型实网、真实业务和部署容量的验收结果。

取消是协作式的，不能强制终止已经开始的同步业务事务。构建通过也不能替代这些验收。
