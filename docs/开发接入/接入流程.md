# 已有项目怎样接入

后台接入现有业务服务，前端复用现有登录。SDK 提供标准聊天入口和基础设施，业务服务继续执行原数据权限与事务。先阅读[新版接入指南](SDK简化接入.md)，已公开旧制品见[0.1.0 教程](../教程/README.md)。

## 后台团队

1. 选择匹配 Java/Boot 的 Starter 和模型适配器依赖，使用配套内部候选。
2. @AiProvider 声明地址、密钥与供应商连接选项；@AiModel 声明模型标识、能力和推理选项；@Agent 引用模型、工具与知识类型。
3. 工具/知识 Bean 调用现有业务服务。原认证已产生 Principal 时默认复用其 name；仅自定义用户/租户结构在原安全配置提供 BusinessPrincipalMapper 字段映射。
4. YAML 只放平台、应用/回调凭据和部署对接信息。SDK 负责注册、租约、回调、原认证链重入、Origin/CORS、URL 凭据拒绝、原权限适配与认证上下文清理；不再手写 AI Filter、Verifier、UiCatalog Bean、scope/read/web。

向前端交付业务 API 前缀、原登录方式、CSRF 要求、允许来源和已发布智能体名；模型密钥、平台管理凭据与内部认证胶囊不交给浏览器。入口权限可以声明在 Agent 上；数据权限仍在业务服务中判断，不另写一套 SDK 数据权限基础设施。

## 前端团队

1. 创建 createClient，baseUrl 使用业务后台入口，auth 选原有 Bearer、Cookie/CSRF 或自定义头。
2. identityKey 使用非秘密的主体/租户/登录代次，注销为 null；普通 token 续期不切换代次。
3. 使用 React/Vue/Vue2 的 ChatPanel；自定义界面用同一 ChatStore、hook 或 Vue2 mixin，不自己实现 SSE/历史缓存。
4. 普通 context 在发送时读取业务数据快照，组件声明提供 props 校验、renderer 与 fallback。入口复用 agents.resolve，筛选项调用公共业务 API，不新增 AI bootstrap 或项目元数据层。

SDK 管理迟到请求、事件、引用和身份切换。断开页面或 reset 不取消后台业务，显式停止才请求取消。

## 平台与验收

平台运维负责应用范围、委托授权、模型/回调出站授权、密钥、HTTPS/SSE、数据库和备份。开发同步草稿与生产核验发布按部署环境分开，业务不重建注册图和发布流程。

先验证实际业务登录下的任务和工具调用，再验证注销/撤销/过期、跨主体和租户、来源重新授权、历史清理、显式取消及重复写防护。同步调用的取消是协作式；不能宣称强制终止已经开始的业务事务。模型厂商实网、真实业务和生产容量分别记录，构建通过不替代这些验收。
