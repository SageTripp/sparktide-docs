# 常见问题

## 是否必须使用某一家模型供应商？

不需要。可以接入支持本平台 Chat Completions 契约的服务，或实现 REMOTE 模型适配。实际端点、工具调用和流式支持应按供应商能力验证。

## 业务系统必须改为 Kotlin 吗？

不需要。Java SDK 核心不依赖 Kotlin，前端使用 TypeScript SDK；任何支持 HTTP 的服务也可直接接入 API。

## 管理员为什么不能直接聊天？

平台管理员负责控制面管理，运行任务需要有明确的业务用户和租户。控制台运行调试要求提供业务身份，防止管理员配置凭据被当作任意用户执行入口。

## appId 相同就能读取同一个会话吗？

不能。平台按应用、用户和租户验证所有权。管理员的应用运行摘要也不等于读取其他用户会话的权限。

## 能否上传 PDF 或直接接入向量数据库？

可以通过托管知识的文件摄入上传 PDF、DOCX、XLSX、PPTX、文本和图片。容器带中英文 OCR，宿主 Jar 需配置引擎；原件、解析和任务有明确资源与权限限制，见[完整操作说明](../开发接入/知识接入/文件上传解析与摄入任务.md)。托管知识可使用[版本化 Embedding 与向量/混合检索](../开发接入/知识接入/向量与混合检索.md)，完成独立索引构建才可发布；文件解析成功不会自动代表向量已就绪。已有向量数据库仍可通过 REMOTE 知识服务连接。

## 发布后能直接修改吗？

不能。创建新版本、更新依赖并切换默认入口。托管知识新版本需要重新导入文档，复制定义不会自动复制文档存储。

## 如何将 SDK 放进已有 Spring 项目？

引入后台 SDK Starter，声明模型和工具/知识，提供 ChatCredentialResolver 并开启 chat.enabled，自动获得 /api/ai 标准 API。前端 createChatClient 或 ChatPanel 直接使用，无需手写 Controller 和请求包装。纯 Java/Kotlin 仍可组合核心服务。业务身份与事务继续由原系统管理。

## 浏览器刷新后为什么需要重新登录控制台？

控制台不持久保存凭据。业务前端应通过自己的身份层获取短期用户令牌，SDK 的 token 函数支持异步刷新。

## 是否已经提供 SaaS、付费套餐或支持 SLA？

本文档介绍自托管产品。公开 SDK、Jar 与镜像下载地址见[版本与获取](../开始使用/版本与获取.md)。商业支持渠道和许可证由维护者补充；当前未提供收费、托管服务或 SLA 承诺。

## 文档站能直接运行平台吗？

不能。GitHub Pages 部署的是静态文档。平台与数据库需要独立服务器或容器；文档中的“部署”章节提供完整步骤。
