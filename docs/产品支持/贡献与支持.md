## 提交问题

描述“希望完成的任务 → 具体步骤 → 实际结果 → 预期结果”。附组件版本、操作系统、部署方式、HTTP 状态和脱敏 traceId。接口受理、运行失败和业务事务失败应分别描述。

安全问题使用维护者公布的私密渠道，不公开 token、密钥、跨租户数据或可直接利用的攻击细节。

## 贡献代码

1. 明确问题和改动范围，先检查现有实现与测试。
2. 遵循对应仓库 AGENTS.md、分支、提交和文档规范。
3. 为行为变化提供验证，避免提交密钥、运行数据和构建产物。
4. 影响 API/事件/SDK 时同步更新契约、使用示例和版本说明。
5. 发布者审核通过后按仓库协作流程合入与发布。

文档问题同样欢迎反馈。本文档用中文按用户任务组织，示例必须对应实际公开接口，产品承诺需有实现依据。

## 后续计划与外部依赖

以下三项已具备实现，但**必须由维护者或使用方提供外部条件**才能完成验收；在取得真实证据前，我们不把它们描述为可用。

| 事项 | 需要提供什么 | 完成后可以确认什么 |
| --- | --- | --- |
| 真实模型、身份与业务接口联调 | 供应商账号与端点、身份供应商配置、一个隔离的业务环境与测试身份 | 真实鉴权与权限拒绝、真实流式与用量回执、工具副作用幂等在实际系统上成立 |
| 生产部署、容量与高可用验收 | 目标主机、域名与证书、目标并发与数据量、留存与合规要求、监控与值班渠道 | TLS 与 SSE 在真实网关下可用、按目标规模达到延迟与错误率、故障转移与恢复时间达标 |
| 公开发行 | 命名空间所有权、许可证选择、远端发布权限、公开支持渠道 | 可用公开发布坐标安装，并有可追溯版本与一致公示的许可证与支持渠道 |

在本地隔离环境中已验证的能力与各自的限制见[能力状态](能力状态.md)。本地验证**不等于**生产能力：容量、恢复时间与供应商行为都需要用真实条件复测。
