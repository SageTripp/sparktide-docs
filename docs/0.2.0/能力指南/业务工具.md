# 业务工具

业务工具是已发布的出站能力。平台校验身份、Schema、租约和副作用状态；DSH 决定是否调用以及如何把工具错误交回模型。平台不自动重试工具，也不重放未知副作用。


## 范围

本文覆盖注册工具和业务回调。模型自带的 PDF 工具见 [界面与文件成果](./界面与文件成果.md)。控制台登记步骤见 [能力资源](../控制台操作/能力资源.md)。

## 步骤

1. 创建 `tools` 草稿。允许字段为 `description`、`endpoint`、`secretRef`、`effect`、`inputSchema`、`outputSchema`、`roles`、`leaseRequired`、`permissions`、`renderWith`。
2. `effect` 只能是 `READ`、`COMPUTE`、`WRITE`、`DANGEROUS`。`WRITE` 与 `DANGEROUS` 沿用确认和副作用分类；校验器不会替工具发明幂等键。
3. `endpoint` 通过结构检查后，出站仍要同时满足 HTTPS（或显式允许 HTTP）、精确 origin 白名单，以及 `secretRef` 的 origin/应用绑定。
4. 发布工具，再把它写入智能体的 `allowedTools` 或 `delegatedCapabilities`。未发布版本不能被新的执行计划选用。
5. 运行中若进入审批，由有权限的应用身份在真实过期时间内同意或拒绝。过期审批不能补交。
6. 工具成功后，只有模型正文实际使用且与可靠记录匹配的引用才会进入回答引用。成功本身不会自动变成引用。

## 配置

定义对象只含下表字段。Schema 使用与模型 `outputSchema` 相同的受限方言，但工具不要求每个属性都列入 `required`。对象仍必须写 `additionalProperties: false`。注册校验接受该方言；装入执行计划时，输出根必须是 `object`，否则返回 503 `TOOL_OUTPUT_SCHEMA_UNSUPPORTED`。业务回调只返回 JSON 对象。

| 字段 | 类型 | 必填或默认 | 含义与怎么填 |
| --- | --- | --- | --- |
| `description` | 字符串 | 可省略 | 交给模型的工具说明。省略或空字符串时，模型看到的是工具资源 `id` |
| `endpoint` | 字符串 | 必填 | 出站地址。结构规则与模型供应商相同；通过 JSON 检查后仍要满足 HTTPS（或显式允许 HTTP）、精确 origin 白名单 |
| `secretRef` | 字符串 | 可省略 | 与模型供应商相同：环境引用名或 `vault:` 凭据。省略则不附加 Bearer。控制台不接收密钥值 |
| `effect` | 字符串 | 必填 | `READ`、`COMPUTE`、`WRITE`、`DANGEROUS`。后两者进入确认和副作用分类。校验器不会另造幂等键 |
| `inputSchema` | 对象 | 必填 | 调用参数。未通过校验的参数不会执行。DSH 可以发起新的纠正调用，平台不修补旧参数 |
| `outputSchema` | 对象 | 必填 | 成功结果的对象形状 |
| `roles` | 字符串数组 | 必填，至少一项 | 只能是 `USER`、`APP_ADMIN`。决定哪类已认证角色可以调用 |
| `leaseRequired` | 布尔或 `null` | 可省略 | `true` 时必须有未过期能力租约，否则不能发布或调用 |
| `permissions` | 字符串数组 | 可省略 | 业务权限名，规则与智能体 `permissions` 相同 |
| `renderWith` | 对象 | 可省略 | 成功后用哪份交互界面呈现。只有 `id` 与 `version`，指向 `ui-capabilities` |

`SPARKTIDE_SECRET_APPLICATIONS` 的值是 `名字=应用;应用`，分号分隔应用。未列出的应用不能使用该引用。`SPARKTIDE_ADMIN_TOKEN`、keyring 和数据库连接串不能登记成业务 secret，进程会拒绝启动。

```json
{
  "description": "按工单号查询当前用户可见的状态",
  "endpoint": "https://tools.example.com/tickets/lookup",
  "secretRef": "TICKETS_TOKEN",
  "effect": "READ",
  "roles": ["USER"],
  "inputSchema": {
    "type": "object",
    "additionalProperties": false,
    "properties": {
      "ticketId": { "type": "string", "minLength": 1, "maxLength": 64 }
    },
    "required": ["ticketId"]
  },
  "outputSchema": {
    "type": "object",
    "additionalProperties": false,
    "properties": {
      "status": { "type": "string" }
    },
    "required": ["status"]
  }
}
```

业务文件成果仍须由成功结果显式返回 `artifact.kind=FILE_ARTIFACT` 及地址字段。平台只投影成果元数据，不保存业务文件字节，不代为抓取 URL。

地址只允许 HTTP(S) 或站内绝对路径，不接受脚本和内嵌用户凭据。

私有业务认证头只出现在受信回调边界。模型、公共历史、SSE 和审计正文不携带该材料。控制台没有业务胶囊，不能代填。

## 结果

工具调用状态为 `DISPATCH_INTENT`、`SUCCEEDED`、`FAILED` 或 `UNKNOWN`。

- `SUCCEEDED` 只说明该次调用有成功结果，不说明业务数据后来被撤销。
- `UNKNOWN` 表示派发后没有可靠终态。先按原 `callId` 核对业务系统，再决定是否人工补偿。
- 进程重启不会把未知副作用改成成功或自动再调用一次。
- 原位编辑会话只会重跑后续回答，不会回滚已经执行的外部写入。
