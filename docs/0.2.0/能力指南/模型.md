# 模型

一次聊天要经过四份已发布定义：供应商决定协议和地址，模型声明厂商模型名与价目，绑定把模型交给某个应用或全局目录，档案决定输出上限、候选顺序和采样参数。平台记录派发意图、用量、回执和本地失败。配置价目用于本地估算和排序，它不是供应商账单。


## 范围

本文说明这四类定义里每个可写字段的类型、是否必填、使用场景和填写示例，并核对发布校验与实际出站。厂商开户、价格谈判和业务 Prompt 不在本文。控制台点击顺序见 [模型与凭据](../控制台操作/模型与凭据.md)。

资源 `id` 与版本 `x.y.z` 写在定义外面。`id` 以小写字母开头，只含小写字母、数字和连字符，最长 64。版本是无前导零的三段号，例如 `1.0.0`，最长 64。定义本身必须是 JSON 对象，规范化后的 JSON 字符串长度不超过 131072（按 JavaScript 字符串长度计）。`status`、`revision`、`publishedAt`、`managedBy` 以及其他未列出的键会被拒绝。校验器不会把缺省值写回文档。

## 步骤

1. 发布供应商，确认 `mode`、`endpoint` 和密钥引用。
2. 发布模型，用 `provider` 指向该供应商，并写上厂商侧的 `modelId`。
3. 发布绑定。应用私有模型省略 `scope`；共用 `global` 目录时显式写 `scope`。
4. 发布档案，至少指向一个绑定。智能体的 `modelProfile` 引用这份档案。
5. 在概览对已发布绑定做合成探测。探测是真实调用，并占用预算。
6. 聊天后在「会话与运行」查看只读账本。用量不完整时保留未知占用，不能补 0。

## 配置

下面示例都是控制台「资源」编辑器里的定义对象。创建时另填资源 `id` 和版本，不要把它们塞进定义。

### 供应商

类型名是 `model-providers`。它描述平台如何访问模型服务，不描述具体模型名。

| 字段 | 类型 | 必填或默认 | 含义与使用场景 | 怎么填 |
| --- | --- | --- | --- | --- |
| `mode` | 字符串 | 必填 | 选择出站协议。`OPENAI_CHAT` 把请求收成 Chat Completions 字段。`REMOTE` 把平台信封按 1.0 交给自建网关 | 只写这两个值之一 |
| `endpoint` | 字符串 | 必填 | 实际 POST 的 HTTP(S) 地址。结构通过后，出站还要求 HTTPS（或进程显式允许 HTTP），且 origin 精确出现在 `SPARKTIDE_ALLOWED_ORIGINS` | 无用户信息、无查询串、无片段、无反斜杠。端口不能是 `0`。整数、十六进制和非规范 IPv4 主机会被拒绝 |
| `secretRef` | 字符串 | 可省略 | 出站 `Authorization: Bearer` 所用的引用名。页面不接收密钥值。省略或空字符串时不附加该头 | 环境名必须已在 `SPARKTIDE_SECRET_NAMES`，且 `SPARKTIDE_SECRET_ORIGINS` 与 endpoint 的 origin 相同，应用列在 `SPARKTIDE_SECRET_APPLICATIONS`。托管凭据写成 `vault:` 加凭据 id，例如 `vault:vendor-chat`；凭据库未启用时返回 503 `CREDENTIAL_STORE_DISABLED` |
| `stream` | 布尔或 `null` | 可省略 | 对 `OPENAI_CHAT`，只有 `true` 才按 SSE 读取，并要求模型把 `capabilities.streaming` 声明为 `true`。`false`、`null` 或省略时读取一整份 JSON，再转成内部帧。`REMOTE` 传输始终要求信封 `stream: true`；这里的 `true` 仍然要求模型声明流式能力 | 厂商支持 SSE 时写 `true`。只支持一次性 JSON 的 OpenAI 兼容接口写 `false` |
| `leaseRequired` | 布尔或 `null` | 可省略 | `true` 时，预览发布和执行都要求该供应商版本有未过期的能力租约。适合必须由对端进程心跳保活的回调。直接调用厂商 URL 时不要设为 `true` | 需要租约时写 `true`，并在发布前完成租约心跳。`null` 与省略一样，不要求租约 |

`SPARKTIDE_ADMIN_TOKEN`、keyring 和数据库连接串不能登记成 `secretRef`。密钥只出现在出站头里，不进入模型正文、公共历史、SSE 或审计正文。

```json
{
  "mode": "OPENAI_CHAT",
  "endpoint": "https://models.example.com/v1/chat/completions",
  "secretRef": "VENDOR_TOKEN",
  "stream": true
}
```

自建网关把厂商协议转换成平台 1.0 帧时，把 `mode` 改成 `REMOTE`，`endpoint` 指向网关。平台不会在两种模式之间自动改写工具参数。

### 模型

类型名是 `models`。一份模型定义绑定一个供应商版本和厂商侧模型名。

| 字段 | 类型 | 必填或默认 | 含义与使用场景 | 怎么填 |
| --- | --- | --- | --- | --- |
| `provider` | 对象 | 必填 | 使用哪一份已发布供应商。发布时该供应商必须能在同一作用域解析 | 只有 `id` 与 `version`。应用内供应商写应用里的 id；`global` 目录中的模型指向 `global` 里的供应商 |
| `modelId` | 字符串 | 必填，1 到 128 个字符 | 放进供应商请求的 `model`。它是厂商模型名，不必符合平台资源 id 规则 | 按厂商文档原样填写，例如 `chat-large`。不要把平台资源 id 误当成厂商模型名 |
| `pricing` | 对象或省略 | 可省略；`null` 视为未配置 | 本地配置价，单位是每百万 token。`ORDERED` 排序不看它。`LOWEST_COST` 要求每个候选都有完整且同币种的价。智能体设置 `maxCost` 时，缺价会使执行准备失败。账本只在输入和输出 token 都完整时算出金额 | 恰好三个键：`currency` 为三位大写字母；`inputPerMillion` 与 `outputPerMillion` 为 0 到 1000000 的有限数字，不能写成字符串 |
| `capabilities` | 对象 | 可省略 | 管理者对能力的声明。未出现的布尔能力是 `UNKNOWN`，调用方不能在请求里临时打开。显式 `false` 是不支持 | 只写下面列出的键。未知键会被拒绝 |

`capabilities` 内的字段：

| 字段 | 类型 | 必填或默认 | 何时要写 | 怎么填 |
| --- | --- | --- | --- | --- |
| `toolCalling` | 布尔 | 可省略 | 智能体允许工具、子智能体、界面，或知识路由为 `AUTO` / `ON_DEMAND` 时，发布要求这里为 `true` | 厂商能返回函数调用就写 `true` |
| `structuredOutput` | 布尔 | 可省略 | 档案带 `outputSchema`，或智能体把它列入 `requiredCapabilities` 时必须为 `true` | 厂商接受严格 JSON Schema 时写 `true` |
| `streaming` | 布尔 | 可省略 | 供应商 `stream` 为 `true` 时必须为 `true`，否则兼容检查失败 | 与供应商的 `stream: true` 成对填写 |
| `vision` | 布尔 | 可省略 | 只有智能体 `requiredCapabilities` 列出它时，发布才要求为 `true` | 当前出站只投影文本和函数调用。图像、文件、音频和推理块会以 `MODEL_FEATURE_UNSUPPORTED` 拒绝，不会改写成正文。写成 `true` 只通过声明检查，不会打开图像输入 |
| `audio` | 布尔 | 可省略 | 与 `vision` 相同，只参与声明检查 | 同样不会把音频放进请求 |
| `contextWindow` | 整数 | 可省略 | 智能体设置 `maxProviderTokens` 或 `maxCost` 时，每个候选都必须有它，否则执行准备失败。省略不会被当成无限窗口 | 1 到 10000000。这是管理者声明的 token 上限。运行时用 UTF-8 字节或字符做保守预检，不是厂商分词器 |
| `maxOutputTokens` | 整数 | 可省略 | 限制这份模型声明能接受的输出上限。档案的 `maxOutputTokens` 不能超过它，也不能超过 `contextWindow` | 1 到 10000000。与 `contextWindow` 同时存在时必须小于或等于窗口 |
| `regions` | 字符串数组 | 可省略 | 智能体写了 `allowedModelRegions` 时，这里必须非空，且每一项都在智能体允许列表内 | 1 到 32 个不重复的地区标签，每项小写字母开头，只含小写字母、数字和连字符，最长 64。标签不放进供应商请求 |

```json
{
  "provider": { "id": "vendor-chat", "version": "1.0.0" },
  "modelId": "chat-large",
  "pricing": {
    "currency": "CNY",
    "inputPerMillion": 1,
    "outputPerMillion": 2
  },
  "capabilities": {
    "toolCalling": true,
    "structuredOutput": true,
    "streaming": true,
    "contextWindow": 128000,
    "maxOutputTokens": 4096,
    "regions": ["cn-local"]
  }
}
```

供应商 `usage` 缺少 `prompt_tokens` 或 `completion_tokens` 时，费用保持未知，不能用 `total_tokens` 代替，也不能补 0。概览里的「未知费用运行」同样不能当成 0 元。

### 绑定

类型名是 `model-bindings`。智能体不直接引用模型，档案引用绑定。

| 字段 | 类型 | 必填或默认 | 含义与使用场景 | 怎么填 |
| --- | --- | --- | --- | --- |
| `model` | 对象 | 必填 | 这份绑定使用的模型版本 | 只有 `id` 与 `version` |
| `scope` | 字符串或省略 | 省略时等于所属应用；`null` 同样按省略处理 | 决定去哪个目录取模型和供应商。省略表示当前应用自己的模型。`global` 表示平台管理员登记在全局目录的模型，供多个应用引用 | 应用私有模型不要写这个键。共用模型写 `"global"`。其他值即使是合法 id，只要不等于所属应用，发布会拒绝 |

全局目录只接受 `model-providers` 与 `models`，路径不带应用段，且只有平台管理员可写。绑定和档案仍放在业务应用里。创建或修改 `scope` 为 `global` 的绑定草稿必须是平台管理员。控制台资源页跟随当前应用，没有单独的全局应用切换。

```json
{
  "model": { "id": "answer-model", "version": "1.0.0" }
}
```

引用全局模型时：

```json
{
  "model": { "id": "answer-model", "version": "1.0.0" },
  "scope": "global"
}
```

### 档案

类型名是 `model-profiles`。智能体通过 `modelProfile` 固定使用一份档案。采样参数和候选顺序都写在这里，不能由单次聊天请求改写。

| 字段 | 类型 | 必填或默认 | 含义与使用场景 | 怎么填 |
| --- | --- | --- | --- | --- |
| `binding` | 对象 | 必填 | 首选绑定。`ORDERED` 时它排在第一位 | `{ "id", "version" }`，指向已发布 `model-bindings` |
| `fallbackBindings` | 对象数组 | 可省略，视为没有后备 | 同一逻辑步里、尚未产出内容时可以尝试的其他绑定 | 每项仍是 `{ "id", "version" }`。与首选合计 1 到 8 个，且 `id@version` 不重复 |
| `maxOutputTokens` | 整数 | 省略时按 1024 检查和使用 | 这次档案允许的完成 token 上限，并作为请求里的 `max_completion_tokens` 缺省值 | 1 到 32768。若模型声明了更小的 `maxOutputTokens` 或 `contextWindow`，档案不能超过声明值 |
| `outputSchema` | 对象 | 可省略 | 要求模型返回一个严格 JSON 对象。存在时，模型必须声明 `structuredOutput: true`。压缩摘要会去掉这个格式 | 根 `type` 必须是 `object`。使用受限方言：`type`、`properties`、`required`、`additionalProperties`、`items`、`enum`、`minimum`、`maximum`、`minLength`、`maxLength`、`minItems`、`maxItems`、`description`、`title`。对象必须 `additionalProperties: false`，并且每个属性都出现在 `required`。嵌套对象同样全部必填。不要写 `$ref`、`pattern`、`format` 或界面用的 `$schema` |
| `routing` | 对象 | 可省略 | 候选如何排序、何时换候选、尝试几次、单次尝试多久 | 见下表。未知键会被拒绝 |
| `parameters` | 对象 | 可省略 | 发给供应商的采样参数。省略的键不会出现在请求里 | 见下表。不能在这里写 `response_format`，格式只来自 `outputSchema` |

`routing` 内的字段：

| 字段 | 类型 | 必填或默认 | 含义与使用场景 | 怎么填 |
| --- | --- | --- | --- | --- |
| `strategy` | 字符串 | 省略为 `ORDERED` | `ORDERED` 按首选再后备的声明顺序。`LOWEST_COST` 用配置价排序：投影请求的 UTF-8 字节数乘 `inputPerMillion`，本次输出上限乘 `outputPerMillion`，精确十进制比较；同价保持原顺序 | 只有一个候选时用 `ORDERED`。要按配置价挑选时，每个候选都写同一 `currency` 的完整 `pricing`，再写 `LOWEST_COST` |
| `fallbackOn` | 字符串数组 | 省略时包含全部四种瞬态错误 | 还没有任何输出、派发结果已经明确、且错误属于该集合时，才换下一个候选。空数组表示这些错误不再换候选 | 只能写且不能重复：`MODEL_UNAVAILABLE`、`MODEL_TIMED_OUT`、`MODEL_RATE_LIMITED`、`MODEL_CIRCUIT_OPEN`。认证失败、协议错误、功能不支持、价格不兼容、预算、取消和已交付内容后的失败不会换候选。`MODEL_CONTEXT_EXCEEDED` 只在请求尚未发出时尝试下一个窗口 |
| `maxAttempts` | 整数 | 省略时等于候选个数 | 这次最多尝试几个已排序候选 | 1 到候选个数。写成 1 表示即使配置了后备也不再尝试 |
| `attemptTimeoutSeconds` | 整数 | 省略时不延长等待 | 单个候选的尝试上限。实际等待取它和本次执行绑定超时的较小值，而执行绑定超时不超过 60 秒 | 1 到 600。写成 30 表示该候选最多等 30 秒。省略不会自动变成 600 秒 |

`parameters` 内的字段：

| 字段 | 类型 | 必填或默认 | 含义与使用场景 | 怎么填 |
| --- | --- | --- | --- | --- |
| `temperature` | 数字 | 可省略 | 控制输出的随机程度：较低值适合稳定的业务回答，较高值适合多样化表达。省略则请求不带该键，沿用供应商默认行为 | 0 到 2 的有限数字 |
| `topP` | 数字 | 可省略 | 限制参与采样的候选词累计概率，较低值收窄候选范围。需要控制表达多样性时使用，通常与温度择一调整；出站时写成 `top_p` | 大于 0 且小于或等于 1 |
| `seed` | 整数 | 可省略 | 希望厂商按种子采样时填写。平台不保证厂商一定会复现 | 0 到 2147483647 |

```json
{
  "binding": { "id": "app-answer", "version": "1.0.0" },
  "fallbackBindings": [
    { "id": "app-backup", "version": "1.0.0" }
  ],
  "maxOutputTokens": 1024,
  "routing": {
    "strategy": "ORDERED",
    "fallbackOn": ["MODEL_UNAVAILABLE", "MODEL_TIMED_OUT"],
    "maxAttempts": 2,
    "attemptTimeoutSeconds": 30
  },
  "parameters": { "temperature": 0.2, "topP": 0.9 },
  "outputSchema": {
    "type": "object",
    "additionalProperties": false,
    "properties": {
      "answer": { "type": "string", "maxLength": 2000 },
      "confidence": { "type": "string", "enum": ["low", "high"] }
    },
    "required": ["answer", "confidence"]
  }
}
```

档案带 `outputSchema` 时，请求使用固定的 `response_format.type = json_schema`，名称是 `sparktide_output`，`strict` 为真。最终正文必须是单个 JSON 对象并符合该 Schema，否则记为 `INVALID_MODEL_OUTPUT`。平台不修补正文，也不因此自动重放。

### 协议与声明检查

`OPENAI_CHAT` 发给厂商的正文只保留模型字段：`model`、`messages`、`stream`、可选的 `tools`、`max_completion_tokens`、`temperature`、`top_p`、`seed`、`response_format`、`tool_choice`。`protocolVersion`、身份、`runId`、`contextWindow`、凭据和业务胶囊不会进入该请求。`function.arguments` 保持厂商返回的字符串，由 DSH 和工具 Schema 校验；平台不改写参数，也不自动重放已执行工具。

`REMOTE` 的 1.0 正文是严格 JSON 对象，并且始终 `stream: true`。工具参数必须能解析成 JSON 对象。它与 `OPENAI_CHAT` 的字符串参数不能混用。

发布图会做声明检查，证据标记为 `DECLARED`，不是厂商探测结论：

- 供应商 `stream: true` 而模型未声明 `streaming: true` 时，发布失败。
- 智能体所需能力为 `UNKNOWN` 或 `false` 时，发布失败，不会静默换一个模型。
- 未声明 `contextWindow` 或模型 `maxOutputTokens` 时产生 `MODEL_LIMIT_UNKNOWN` 警告；一旦档案输出超过已声明上限，则变为错误。
- 根费用上限要求子模型声明上下文窗口和完整价格，且币种一致；缺失或不匹配时执行准备失败。根供应商 token 上限要求上下文窗口，不因此额外要求价格或币种。

公共会话 SSE 仍使用 `Last-Event-ID`。供应商 `stream` 不表示可以省略这个游标，也不表示预览帧已经可靠提交。

### 探测、配额与人工证据

合成探测只针对已发布绑定。`TEXT` 始终执行。可另选 `TOOL_CALLING`、`STREAMING`、`STRUCTURED_OUTPUT`。`OPENAI_CHAT` 且供应商 `stream` 不是 `true` 时，`STREAMING` 记为 `UNSUPPORTED`，不会发出该次流式请求。探测输出上限取模型声明的 `maxOutputTokens` 与 32 的较小值；模型未声明时用 32。健康初始 `CLOSED` 只表示还没有成功探测。恢复发送前要显式探测，并按服务端 generation 复核。

配额策略的字段和保存方式见 [模型与凭据](../控制台操作/模型与凭据.md)。未知用量不会显示成 0。

人工对账 `POST .../model-invocations/{invocationId}/reconcile` 只给终态且已派发的调用追加证据。它不改物理回执，不释放业务 `UNKNOWN`，也不统一改写根 token、Run 费用和祖先预算。

探测预算修正 `POST .../quota-reservations/{reservationId}/reconcile` 只处理 `purpose=SYNTHETIC_PROBE`。它按证据替换 held/charged。探测回执、健康和请求计数不变。业务预留会被拒绝。

压缩摘要、标题、建议和下一步建议若调用模型，仍计入原运行或对应元数据操作的预算。

## 结果

- 重置管理隔离状态会改变发送资格。控制台要求填写理由并勾选确认，且不会自动重发 Run。
- 瞬时可恢复错误名只有 `MODEL_UNAVAILABLE`、`MODEL_TIMED_OUT`、`MODEL_RATE_LIMITED`、`MODEL_CIRCUIT_OPEN`。它们不授权自动重放未知结果。
- 候选已经向会话交付内容，或派发意图仍是未知提交时，不再切换后备绑定。
- 配置价、供应商用量和人工证据是三份不同事实。
