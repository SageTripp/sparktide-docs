# 会话交互

会话、运行和公共事件以 PostgreSQL 为准。原生流只在可靠前缀之后附加无序号的正文预览。预览断开不会自动取消运行。


## 范围

本文说明聊天、历史、跟进、审批、问卷、编辑和元数据。控制台实际按钮见 [运行与审批](../控制台操作/运行与审批.md)。

## 步骤

1. 使用应用身份创建会话。目录只返回本人的标题、时间和计数，按创建时间倒序，相同时按会话 ID 倒序。继续聊天、改名和更新摘要不改变列表位置。
2. 发送消息时带 `Idempotency-Key`。同一所有者、种类和请求键先查幂等。受理响应是 `QUEUED`，表示已接受，不是已经生成完回答。
3. 读取可靠事件使用 `Last-Event-ID: {runId}:{sequence}`。没有 `after` 查询参数可以替代这个游标。
4. 需要未落库尾部时，先读流能力，再打开 `GET /v1/apps/{app}/runs/{runId}/stream`。可靠事件仍从原 `/events` 按序号恢复。
5. 活动运行期间可以提交 `QUEUE` 或 `STEER` 跟进。`STEER` 必须有服务端返回的真实 `activeRunId`，并且能力声明包含该模式。
6. `WRITE` / `DANGEROUS` 工具或问卷会让运行进入 `WAITING_CONFIRMATION`。决定提交后等待运行状态变化，不要立刻再提交一次。
7. 结束或取消后核对终态：`SUCCEEDED`、`FAILED`、`CANCELLED` 或 `TIMED_OUT`。未知回执先用原键只读核对。

会话归档和恢复返回闭合的 `ConversationArchival`：只有 `protocolVersion`、`id`、`archived`、`archivedAt`。重复归档保留原时间，恢复后时间为 `null`。历史仍单独授权，不删除正文。当前控制台只显示「已归档」标记，没有归档、恢复或重命名按钮。

## 配置

| 能力 | 合同要点 | 边界 |
| --- | --- | --- |
| 历史分页 | 会话 GET 的 `limit` 为 1 到 20，可带不透明 `before` | 执行库格式 21 把公开展示消息放在 `st_node_conversation_message`。编辑后旧游标返回 409 |
| 原位编辑 | 只处理服务端 `editable=true` 的用户主消息 | 会创建新 Run。已执行的工具和外部写入不回滚 |
| 摘要 / 标题 | 独立元数据操作，结果缓存在会话元数据 | `sourceHash` 相对当前成功窗口判断 `stale`。重复读取不重新调用模型。失败轮次只作为未完成待办 |
| 下一步建议 | `POST .../suggestions`，`count` 为 1–5 或 `byAi`，省略为 3，必带幂等键 | 不写聊天正文，不执行建议里的动作。客户端 `nextSuggestions:0` 为关闭 |
| `QUEUE` | 受理后 `runId` 为空，等当前队列派发 | 元数据挂起时不会拿聊天 Run 去消费这条队列 |
| `STEER` | 引导当前活动 Run | 没有活动 Run 时客户端不得伪造目标 |
| `PAUSE` / `RESUME` / `STOP` | `PAUSE` 只停止后续派发；`STOP` 同时请求取消活动 Run | `RESUME` 若要求新鲜业务认证，控制台不能代填 |
| 原生预览 | 预览帧没有可靠事件 id | 正文读取许可最长 10 秒，从完整校验起算。重启后只能恢复已提交前缀 |
| 并发 | 全局在途请求上限 32；同一身份并发上限 8 | 超限返回 429，并带 `Retry-After` |

业务网关自己的 `/api/ai/streaming/capabilities` 与 `/api/ai/runs/{id}/stream` 不在本平台进程内。平台侧新增的是 `/v1` 下的能力声明和运行流。

原生流的容量和延迟没有对外数值保证。设计记录仍要求用真实基线验收慢续约、撤权、断线和预算并发；不能把端点存在写成性能承诺。

## 结果

- 公共事件里的 `message.completed` 带真实 `createdAt`、`finishedAt`；失败保留 `errorCode`。
- 断流、刷新控制台或退出登录都不会取消已经受理的服务端运行。要停止须显式调用取消。
- `COMMIT` 未知时保留占用和围栏，不自动退款或重放。
- 应用活动运行分页 `GET /v1/apps/{app}/activity/runs` 未装配。普通运行查询不能代替它。
