# 智能体

智能体定义描述允许使用的模型档案、工具、知识、子智能体和界面。真正的循环只在 DSH `0.2.1-rc.3` 中运行。平台负责身份、固定发布计划、预算、取消和可靠落库。


## 范围

本文说明注册字段、默认入口、预算和压缩边界。控制台点击顺序见 [能力资源](../控制台操作/能力资源.md)。

## 步骤

1. 在应用内创建 `agents` 草稿。资源 `id` 为小写字母开头、仅含小写字母、数字和连字符，最长 64。版本必须是明确的 `x.y.z`。
2. 定义里只使用允许字段：`systemPrompt`、`modelProfile`、`allowedTools`、`allowedKnowledge`、`allowedAgents`、`allowedUi`、`delegatedCapabilities`、`limits`、`entryPolicy`、`permissions`、`requiredCapabilities`、`allowedModelRegions`、`knowledgeRouting`。平台元数据如 `status`、`revision` 不能写进定义。
3. `delegatedCapabilities` 每项形如 `tools|knowledge|ui-capabilities/{id}@{x.y.z}`。子图超过 256 个访问节点会被拒绝。
4. 保存草稿后单独发布。发布后正文不能在原版本上修改；变更要新版本。
5. 由应用管理员或平台管理员把默认 Agent 指到一个真实的 `PUBLISHED` 版本。未设置默认 Agent 的应用不能当成可聊天。
6. 用应用身份发起会话。平台管理员凭据不能代替业务身份执行会话。

## 配置

定义里的引用都是 `{ "id", "version" }`，不能多写键。模型档案的字段见 [模型](./模型.md)。

| 字段 | 类型 | 必填或默认 | 怎么填 |
| --- | --- | --- | --- |
| `systemPrompt` | 字符串 | 必填，1 到 32768 个字符 | 写给模型的固定说明。它不是用户消息，也不能代替工具权限 |
| `modelProfile` | 对象 | 必填 | 指向已发布 `model-profiles`。聊天使用该档案的绑定、输出上限和采样参数 |
| `allowedTools` | 对象数组 | 可省略 | 该智能体可调用的已发布工具。非空时，模型必须声明 `toolCalling: true` |
| `allowedKnowledge` | 对象数组 | 可省略 | 可检索的知识版本，最多 64 个且不能重复。知识定义本身见 [知识问答](./知识问答.md) |
| `allowedAgents` | 对象数组 | 可省略 | 可委派的子智能体。非空时同样要求 `toolCalling: true` |
| `allowedUi` | 对象数组 | 可省略 | 可呈现的交互界面。非空时要求 `toolCalling: true` |
| `delegatedCapabilities` | 字符串数组 | 可省略 | 每项为 `tools`、`knowledge` 或 `ui-capabilities`，后接 `/{id}@{x.y.z}`。子图超过 256 个访问节点会被拒绝 |
| `requiredCapabilities` | 字符串数组 | 可省略 | 只接受 `toolCalling`、`structuredOutput`、`vision`、`audio`、`streaming`，不能重复。模型必须把列出的项声明为 `true`。`vision` 与 `audio` 当前仍不能把图像或音频送出 |
| `allowedModelRegions` | 字符串数组 | 可省略 | 非空时，每个候选模型的 `regions` 必须是它的子集，且模型必须声明地区。标签规则与模型地区相同 |
| `permissions` | 字符串数组 | 可省略 | 业务权限名，最多 64 个不重复项。每项以字母开头，最长 128，可含数字、下划线、点、冒号和连字符 |
| `limits` | 对象 | 可省略；省略时按各字段缺省值 | 见下表。祖先限制仍然生效。`maxSteps` 或 `maxToolCalls` 写成 `-1` 只取消这一项计数，不取消预算、授权和取消 |
| `entryPolicy` | 对象 | 可省略；省略时 `mode` 为 `APPLICATION` | 见下表。请求正文里的身份字段不会被当成已认证主体 |
| `knowledgeRouting` | 对象 | 可省略 | 见下表。`AUTO` 与 `ON_DEMAND` 要求模型声明工具调用 |

`limits` 只接受这些键。`maxTokens` 与 `maxBudgetUnits` 不能同时写；前者是字符预算的旧名，不是供应商 token。

| 字段 | 类型与范围 | 省略时 | 使用场景 |
| --- | --- | --- | --- |
| `maxSteps` | `-1`，或 1 到 32 | 8 | 模型循环步数。`-1` 表示这一项不封顶 |
| `maxToolCalls` | `-1`，或 0 到 64 | 16 | 工具调用次数。`0` 把这项上限设为 0 |
| `maxDepth` | 0 到 8 | 3 | 子智能体嵌套深度 |
| `timeoutSeconds` | 1 到 600 | 120 | 单步超时秒数。交给模型适配器的单次等待不超过 60 秒；更大的值仍参与运行看门狗，不会把单次模型等待延长到 600 秒 |
| `maxBudgetUnits` | 256 到 1000000 | 沿用 `maxTokens`，再没有则是 32000 | 字符预算 |
| `maxTokens` | 256 到 1000000 | 32000 | 只在不写 `maxBudgetUnits` 时作为字符预算 |
| `maxAgentCalls` | 0 到 64 | 8 | 子智能体调用次数 |
| `maxProviderTokens` | 0 到 1000000000000 的整数 | 不设供应商 token 上限 | 一旦设置，每个候选模型都必须声明 `contextWindow` |
| `maxCost` | 对象，恰好 `currency` 与 `amount` | 不设金额上限 | `currency` 为三位大写字母。`amount` 是十进制字符串，例如 `"20"` 或 `"0.50"`，不能写成 JSON 数字。每个候选都要有同币种的完整 `pricing` 和 `contextWindow` |

`entryPolicy`：

| 字段 | 取值 | 何时使用 |
| --- | --- | --- |
| `mode` | `APPLICATION`（默认）、`RESTRICTED`、`INTERNAL_ONLY` | `APPLICATION` 不再按名单收窄。`RESTRICTED` 至少填写下面一项。`INTERNAL_ONLY` 不能设为应用默认入口 |
| `roles` | `USER`、`APP_ADMIN` | 仅 `RESTRICTED`。名单最多 256 项，每项 1 到 128 个字符，且不能重复 |
| `subjects` | 字符串数组 | 仅 `RESTRICTED`。匹配已经认证的主体 |
| `tenants` | 字符串数组 | 仅 `RESTRICTED`。匹配已经认证的租户 |

`knowledgeRouting` 的数值都有缺省，省略时仍按缺省执行，不会写回定义：

| 字段 | 类型与范围 | 省略时 | 含义 |
| --- | --- | --- | --- |
| `mode` | `EAGER`、`AUTO`、`ON_DEMAND` | `AUTO` | `EAGER` 在回合开始时用用户问题检索并注入资料，不安装知识工具。`ON_DEMAND` 只安装知识工具，等模型调用。`AUTO` 两者都做 |
| `failurePolicy` | `FAIL_FAST`、`SKIP_TRANSIENT` | `FAIL_FAST` | `SKIP_TRANSIENT` 只跳过 `KNOWLEDGE_UNAVAILABLE`、`KNOWLEDGE_TIMED_OUT`、`KNOWLEDGE_RATE_LIMITED` |
| `rerank` | `NONE`、`LEXICAL` | `NONE` | `LEXICAL` 在来源融合后再做词法重排 |
| `maxSources` | 1 到 16 | 4 | 一次最多使用的来源数 |
| `topK` | 1 到 50 | 8 | 路由层每个来源保留的条数。它独立于知识定义里 1 到 10、缺省 3 的 `topK` |
| `maxRetrievals` | 1 到 64 | 8 | 检索次数上限 |
| `maxQueriesPerSource` | 1 到 16 | 3 | 每个来源的查询次数 |
| `sourceTimeoutSeconds` | 1 到 60 | 15 | 单个来源超时 |
| `sourceMaxChars` | 1 到 65536 | 16000 | 单个来源进入上下文的字符上限 |
| `maxContextChars` | 1 到 65536 | 16000 | 检索资料进入上下文的总字符上限 |
| `rules` | 对象数组，最多 64 | 空 | 每条必须指向 `allowedKnowledge` 中的一个版本，并用 `queryTerms`、`tags`、`contextEquals` 或 `always: true` 至少一个条件选中它 |

规则对象还可写 `priority`，整数 0 到 100，省略为 0。`queryTerms` 与 `tags` 各最多 16 个不重复、去空白后非空、最长 64 的字符串。`contextEquals` 最多 16 个键，键以字母开头，只含字母、数字和下划线，最长 64；值是最长 128 的字符串。它只与可信服务端上下文比较。

```json
{
  "systemPrompt": "只根据已授权资料回答，并保留引用标记。",
  "modelProfile": { "id": "default-profile", "version": "1.0.0" },
  "allowedTools": [{ "id": "ticket-lookup", "version": "1.0.0" }],
  "allowedKnowledge": [{ "id": "ops-manual", "version": "1.0.0" }],
  "limits": { "maxSteps": 8, "maxToolCalls": 16, "maxBudgetUnits": 32000 },
  "entryPolicy": { "mode": "APPLICATION" },
  "knowledgeRouting": {
    "mode": "AUTO",
    "failurePolicy": "FAIL_FAST",
    "rules": [{
      "knowledge": { "id": "ops-manual", "version": "1.0.0" },
      "queryTerms": ["工单"],
      "priority": 10
    }]
  }
}
```

其余运行边界：

| 项 | 当前行为 |
| --- | --- |
| 子智能体文本 | 子调用的正文只通过委派结果返回，不能直接变成父级 `text.delta` |
| 上下文压缩 | 使用同版 `@deepseek-ai/dsh-compaction-basic`。消息数达到 200 时提前压缩，避开 256 条投影上限。第一轮没有历史时不压缩新问题 |
| 压缩摘要 | 最多 1536 个输出 token，并受原模型配置约束；提示要求正文尽量控制在 600 字内。摘要调用计入原运行预算，不退还已消耗额度 |
| 单活 | 执行器用专用 PostgreSQL 连接持有顾问锁 `pg_try_advisory_lock(1937006964, 3)`。锁被占用时新进程报 `Another Node executor owns this database` 并退出 |

压缩保留目标、约束、事实、精确标识、来源、未知项和待办。原始会话日志仍在 PostgreSQL。压缩不是无损记忆，也不取消授权和取消。

## 结果

- 同一会话同时只有一个非元数据的活动聊天 Run，以及最多一个活动的会话元数据 Run。
- 重启时，仍处于 `QUEUED`、`RUNNING`、`WAITING_CONFIRMATION` 的运行会被收成失败，并推进围栏。审批记录保留，不会自动批准或继续执行。
- `DISPATCH_INTENT` 且所属运行已终态的工具调用会被标成 `UNKNOWN` / `PROCESS_RESTARTED`，不会自动重放。
- 固定计划在发布后绑定。草稿变更不影响已经准入的运行，直到新的发布和入口切换生效。
