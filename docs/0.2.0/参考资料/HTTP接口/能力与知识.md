## 列出应用注册表版本 {#get-v1-apps-app-kind}

`GET /v1/apps/{app}/{kind}`

用途：按资源种类列出指定应用注册表中的版本，供应用管理员查看草稿与已发布条目。身份：该应用的 APP_ADMIN，或 PLATFORM_ADMIN。USER 不能列出注册表。路径 app 与 kind 只定位集合。读取 global 模型绑定定义并不额外放行业务正文。请求：路径参数 app 与 kind 均必填，无请求体。响应：200 返回 Registry 数组。错误：合同声明 400、401、403、404、409、410、412、413、429、500、503 为 Error 信封，502 为上游失败。流程：认证后只读枚举该种类下的注册版本；不保存草稿、不发布、不撤销。种类或应用不可见时按声明错误返回，不能靠更换模型或 Context 绕过。本说明只解释协议用途，不表示该 Node 接口已经生产验收。

### 请求参数

| 名称 | 位置 | 必填 | 类型与说明 |
| --- | --- | --- | --- |
| app | path | 是 | string；目标应用标识，仅用于确定作用域；不构成认证或授权依据。 |
| kind | path | 是 | string；目标注册资源类别，允许值以当前操作的枚举为准。 |

## 保存应用注册表草稿 {#post-v1-apps-app-kind}

`POST /v1/apps/{app}/{kind}`

用途：在指定应用的某一资源种类下保存注册表草稿，供后续读取、修订和发布。身份：该应用的 APP_ADMIN，或 PLATFORM_ADMIN，用于保存仍可编辑的草稿。若草稿是 scope 为 global 的 model-bindings，写入时还必须是 PLATFORM_ADMIN；已存在的全局引用仍可由应用管理员日后发布。USER 不能写草稿。路径、模型与 Context 不是授权依据。请求：路径 app 与 kind 必填；可选 If-Match；必须提交 application/json 的 Registration。响应：200 返回保存后的 Registry。错误：合同声明 400、401、403、404、409、410、412、413、429、500、503 为 Error 信封，502 为上游失败。流程：更新已有草稿时应携带并核对 If-Match，412 冲突必须重新读取后显式决定，不得自动重试覆盖。保存草稿本身不发布版本。本说明只解释协议用途，不表示该 Node 接口已经生产验收。

### 请求参数

| 名称 | 位置 | 必填 | 类型与说明 |
| --- | --- | --- | --- |
| app | path | 是 | string；目标应用标识，仅用于确定作用域；不构成认证或授权依据。 |
| kind | path | 是 | string；目标注册资源类别，允许值以当前操作的枚举为准。 |
| If-Match | header | 否 | string；目标资源当前修订号，格式遵循当前接口；412时保留本地内容并读取核对，不自动换用新修订重发。 |

### 请求正文

Content-Type：`application/json`。正文必填。

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| id | string | 是 | 本次保存的注册表资源标识。 |
| version | string | 是 | 本次保存的草稿版本号。 |
| definition | [Definition](./数据结构.md#schema-definition) | 是 | 该 kind 对应的定义对象，例如智能体、工具、知识或模型。种类由路径决定，不在这个字段里重复。 |
