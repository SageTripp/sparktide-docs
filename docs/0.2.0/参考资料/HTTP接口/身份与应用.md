## 平台管理员创建应用 {#post-v1-apps}

`POST /v1/apps`

用途：由平台管理员登记一个新应用，作为后续凭证、注册表和运行入口的归属对象。身份：安全方案为 BearerAuth，摘要限定平台管理员；应用标识、模型名称和用户 Context 不能代替该管理身份，管理者没有业务正文旁路。请求：必须提交 application/json 的 CreateApplication。响应：200 返回新建的 Application。错误：合同声明 400、401、403、404、409、410、412、413、429、500、503 为 Error 信封，502 为上游失败。流程：校验载荷后创建；写操作失败不得自动重试，以免重复登记。客户端应以返回的应用标识继续后续配置，不能把创建结果当成业务正文授权。本说明只解释协议用途，不表示该 Node 接口已经生产验收。

### 请求正文

Content-Type：`application/json`。正文必填。

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| id | string | 是 | 平台管理员创建应用时指定的应用标识，之后出现在路径 {app}。它不是访问权限。 |
| name | string | 否 | 应用的显示名称，可以省略。省略不等于没有应用标识。 |

## 更新应用名称和运行状态 {#put-v1-apps-app}

`PUT /v1/apps/{app}`

用途：更新指定应用的名称、运行状态及相关治理配置，归档只改变状态，不物理删除数据。身份：该应用的 APP_ADMIN，或 PLATFORM_ADMIN，并必须用 If-Match 核对修订。USER 被拒绝。403 即缺少上述管理身份。路径 app、模型与 Context 不是授权依据。请求：路径 app 必填；必须携带 If-Match；请求体为 JSON，字段包括 name、status、reason，以及 permissionProvider、contextProvider、evaluationGate。响应：200 返回更新后的 Application。错误：400 表示无效状态或默认入口，403 表示缺少应用管理权限，412 表示修订冲突。流程：调用方必须用当前修订核对 If-Match，冲突后重新读取再决定是否提交；写操作不得自动重试或覆盖冲突版本。本说明只解释协议用途，不表示该 Node 接口已经生产验收。

### 请求参数

| 名称 | 位置 | 必填 | 类型与说明 |
| --- | --- | --- | --- |
| app | path | 是 | string；目标应用标识，仅用于确定作用域；不构成认证或授权依据。 |
| If-Match | header | 是 | string；目标资源当前修订号，格式遵循当前接口；412时保留本地内容并读取核对，不自动换用新修订重发。 |

### 请求正文

Content-Type：`application/json`。正文必填。

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| name | string | 否 | 要改成的应用显示名称，长度 1 到 128。至少要改一个字段。；minLength: 1；maxLength: 128 |
| status | string | 否 | 应用运行状态：DRAFT、ACTIVE、SUSPENDED 或 ARCHIVED。改变状态不会发布注册表版本。；enum: ["DRAFT","ACTIVE","SUSPENDED","ARCHIVED"] |
| reason | string | 否 | 这次修改应用的原因，最长 512。；maxLength: 512 |
| permissionProvider | [BusinessProvider](./数据结构.md#schema-businessprovider) | 否 | 应用使用的业务权限提供方。权限由其决策，应用标识本身不是授权。 |
| contextProvider | [ContextProvider](./数据结构.md#schema-contextprovider) | 否 | 应用使用的上下文提供方。 |
| evaluationGate | [EvaluationGate](./数据结构.md#schema-evaluationgate) | 否 | 发布是否必须先通过评测门禁。 |

## 为应用签发凭证 {#post-v1-apps-app-tokens}

`POST /v1/apps/{app}/tokens`

用途：由平台管理员为指定应用签发一枚新凭证，供该应用的受控调用使用。身份：安全方案为 BearerAuth，摘要限定平台管理员；路径 app、模型与用户 Context 不是授权依据，管理身份没有业务正文旁路。请求：路径 app 必填，必须提交 application/json 的 CreateToken。响应：200 返回签发结果 Token。错误：合同声明 400、401、403、404、409、410、412、413、429、500、503 为 Error 信封，502 为上游失败。流程：校验载荷后签发；写操作失败不得自动重试，以免重复签发。客户端应保存返回结果并按最小范围使用。失败后不得自动重试签发，应先核对凭证元数据再决定是否再次提交。本说明只解释协议用途，不表示该 Node 接口已经生产验收。

### 请求参数

| --- | --- | --- | --- |
| app | path | 是 | string；目标应用标识，仅用于确定作用域；不构成认证或授权依据。 |

### 请求正文

Content-Type：`application/json`。正文必填。

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| subjectId | string | 是 | 新凭证所代表的业务主体。长度 1 到 128。；minLength: 1；maxLength: 128 |
| tenantId | string | 否 | 新凭证绑定的租户标识，最长 128。省略或 null 按空租户标识处理；空值不是所有租户的通配授权。需要按租户隔离时填写业务映射后的租户标识。；maxLength: 128 |
| role | 对象 | 否 | 新凭证的角色，只能是 USER 或 APP_ADMIN。省略时合同声明的缺省是 USER。；default: "USER"；enum: ["USER","APP_ADMIN"] |
| ttlSeconds | integer | 否 | 凭证计划存活的秒数，范围 60 到 2592000。省略时合同声明的缺省是 86400 秒。；default: 86400；minimum: 60；maximum: 2592000 |

## 更新控制台个人资料 {#put-v1-me-profile}

`PUT /v1/me/profile`

用途：修改当前控制台身份的显示名称和头像颜色。身份：BearerAuth，仅 PLATFORM_ADMIN 和 APP_ADMIN。只允许改这两项，不改变身份和权限。相同 appId、tenantId、subjectId 共享资料；共享平台凭据也共享资料。appId、模型与 Context 不是授权依据，也不能借资料接口访问业务正文。请求：If-Match 必填，为当前 revision 的十进制字符串，可带双引号；未设置资料时为 0，缺失或过期返回 412。正文必含 displayName 与 avatarColor。名称去首尾空白后为 1 至 64 个 Unicode 字符且不含控制字符，颜色仅五种枚举。响应：200 返回更新后的 ConsoleProfile。错误：合同列出的结构化响应包括400（请求字段或格式非法）；401（认证缺失或失效）；403（角色、作用域或当前业务权限不允许）；412（请求修订与当前记录不符，须只读核对后显式决定）。流程：先 GET 取得修订，核对 If-Match 后提交一次。412 必须重新读取并显式核对，禁止自动重试。共享资料意味着一次更新会影响同一主体的其他控制台入口。  补充约束：仅允许修改显示名称与头像颜色，不改变身份和权限。相同 appId、tenantId、subjectId 共享资料；共享平台凭据也共享资料。

### 请求参数

| 名称 | 位置 | 必填 | 类型与说明 |
| --- | --- | --- | --- |
| If-Match | header | 是 | string；当前 revision 的十进制字符串，可带双引号。未设置资料时为 0；缺失或过期返回 412。 |

### 请求正文

Content-Type：`application/json`。正文必填。

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| displayName | string | 是 | 控制台里显示的名称。它不改变登录主体。；minLength: 1；maxLength: 64 |
| avatarColor | string | 是 | 控制台头像使用的颜色。它不是权限标记。；enum: ["blue","teal","violet","amber","slate"] |

### 响应

| HTTP | 说明 | 类型 |
| --- | --- | --- |
| 200 | 当前身份的展示资料 | application/json：[ConsoleProfile](./数据结构.md#schema-consoleprofile) |
| 400 | 路径、查询、请求头或正文没有通过该操作的校验。按 error.code 修正后再发新请求，不要原样重放写操作。 | application/json：[Error](./数据结构.md#schema-error) |
| 401 | 没有可用身份。平台入口对缺少 Bearer、非法令牌、过期或已吊销凭据使用 UNAUTHENTICATED。 | application/json：[Error](./数据结构.md#schema-error) |
| 403 | 身份已经识别，但角色、应用范围或资源所有权不允许。不要改 appId 或 context 绕过。 | application/json：[Error](./数据结构.md#schema-error) |
| 412 | 修订或前置条件与服务端当前值不一致。用响应前重新读到的 revision 明确重试，不要自动覆盖。 | application/json：[Error](./数据结构.md#schema-error) |

### 错误

失败响应包含 `error.code`、`error.message`、`error.traceId`、`error.retryable` 和 `error.details`。以下列出本操作的入口错误；认证、限流以及后续领域处理失败详见[公共错误码](../公共错误码.md)。HTTP 状态与错误码不是一对一关系。

| HTTP | error.code | 触发条件 | 处理 |
| --- | --- | --- | --- |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 读取 JSON 正文时 Content-Type 不是 application/json，charset 只允许 utf-8。 | 改为 JSON 正文。合同若未列出 415，入口仍返回该码。 |
| 413 | `REQUEST_TOO_LARGE` | JSON 正文超过该端点字节上限。超限在收完有界丢弃后返回，避免连接被提前重置。 | 缩小正文。不要把截断后的正文自动重放。 |
| 400 | `INVALID_REQUEST` | 正文不是合法 UTF-8、被中断，或 Content-Length 与实际字节不一致。 | 修正正文后再提交。 |
| 400 | `INVALID_REQUEST` | 个人资料入口不接受查询字段，路径不能包含反斜杠。 | 只提交显示名和头像颜色。这不是平台身份。 |

业务校验、存储及运行准备还可能返回领域错误，请按[公共错误码](../公共错误码.md#领域错误码索引)中的代码和处理建议判断。任务已经受理后发生的失败，应读取运行或任务记录。
