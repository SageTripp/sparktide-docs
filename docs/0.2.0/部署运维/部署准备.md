# 部署准备

先确认运行时、数据库和单活约束，再选择容器或独立进程。本文不执行构建、拉镜像或初始化。


## 范围

准备完成后继续 [Docker部署](./Docker部署.md) 或 [独立进程部署](./独立进程部署.md)。变量含义见 [环境变量](./环境变量.md)。

## 步骤

1. 安装与根 `package.json` 一致的 Node `24.22.1` 和 npm `10.9.4`。仓库用 `mise.toml` 固定版本，不要改机器上其他项目的全局 Node。
2. 准备 PostgreSQL 17。容器编排使用镜像 `postgres:17`、库名 `sparktide`、用户名 `sparktide`。口令没有默认值。
3. 选定宿主端口。编排默认把容器 `18092` 发布到 `127.0.0.1:18092`。若端口已有服务，设置 `SPARKTIDE_NODE_HOST_PORT`，不要改掉既有服务。
4. 决定是否需要文档解析。默认镜像没有 Java。需要时再使用构建目标 `runtime-parser`，或在独立进程配齐解析器四项。Java 只运行独立抽取引擎，不运行平台服务。
5. 准备管理令牌、数据库口令和可选的 32 字节 keyring。用当前进程读取，不要写进文件：

```powershell
$env:SPARKTIDE_ADMIN_TOKEN = Read-Host 'SPARKTIDE_ADMIN_TOKEN'
$env:SPARKTIDE_DB_PASSWORD = Read-Host 'SPARKTIDE_DB_PASSWORD'
```

6. 确认同一 PostgreSQL 上只会启动一个启澜执行器。第二个进程会在取得顾问锁失败后退出。
7. 留出维护窗口。初始化会安装或升级 `st_node_*` 表，不会转换外部业务库，也不会重放业务任务。

`Read-Host` 默认会回显。处理完立即执行 `Remove-Item Env:SPARKTIDE_ADMIN_TOKEN` 和 `Remove-Item Env:SPARKTIDE_DB_PASSWORD`。需要不回显时，先读入 `SecureString`，只在当前进程转成环境变量，用完同样删除。

## 配置

| 检查项 | 要求 |
| --- | --- |
| 操作系统账户 | 独立进程使用能读字体、解析器和连接库的账户。容器运行用户是 uid/gid `10001`，不能写镜像根目录 |
| 磁盘 | 数据库卷名是 `node-postgres-data`。改项目名 `sparktide-node-candidate` 会改变默认卷定位 |
| 网络 | 默认不开放 CORS，不信任 `Forwarded` / `X-Forwarded-For`。反代须按 [网络与认证](./网络与认证.md) 单独设计 |
| 可选镜像 | 测试文档中的 Redis 只用于测试。当前 `compose.yaml` 没有 Redis 服务 |
| 可选 OCR | `runtime-parser` 不安装 OCR，也不是安全沙箱 |
| 字体 | 只有要生成 PDF 时才准备 `SPARKTIDE_REPORT_FONT_FILE` 指向的可读字体 |

构建使用 `npm ci`，版本锁在 `package-lock.json`。不要在部署机上改依赖范围来“凑齐”一个能启动的组合。

## 结果

- 准备完成的标志是：运行时版本可核对、目标库已确认、口令只存在于当前进程、并且决定了唯一执行器。
- 尚未初始化时，服务即使启动也会因缺少表或执行库版本不是 21 而失败。这是预期结果，不是去手改元数据。
- 本地测试成功不能代替生产身份源、模型厂商、长历史和恢复演练。
