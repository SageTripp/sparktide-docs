# 独立进程部署

不用容器时，在仓库根目录用固定的 Node 构建并启动 `dist/apps/server/src/main.js`。进程默认只听 `127.0.0.1:18092`，且不会自动建表。


本文命令只作为目标机操作说明，不在文档编写环境执行。

## 范围

与 [Docker部署](./Docker部署.md) 二选一或分环境使用。两边不能同时成为同一数据库的执行器。变量见 [环境变量](./环境变量.md)。

## 步骤

1. 进入平台仓库根目录，安装锁定依赖并构建。`npm start` 依赖构建产物，不监听源码热更新。

```powershell
mise install
mise exec -- npm ci
mise exec -- npm run build
```

只编译服务端、不编译控制台时使用 `mise exec -- npm run build:node`。若 `SPARKTIDE_NODE_CONSOLE_ENABLED` 仍为默认的 `true`，缺少控制台产物会导致启动失败。

2. 注入目标库。把占位符换成操作者自己的主机、库名和已编码口令，不要使用示例口令。

```powershell
$env:SPARKTIDE_NODE_DATABASE_URL = Read-Host 'postgres://<用户>:<已编码口令>@<主机>:5432/<库名>'
$env:SPARKTIDE_ADMIN_TOKEN = Read-Host 'SPARKTIDE_ADMIN_TOKEN'
```

3. 显式初始化。开关只在这条命令的进程里保留。

```powershell
$env:SPARKTIDE_ALLOW_DATABASE_INITIALIZATION = 'true'
mise exec -- npm run db:initialize
Remove-Item Env:SPARKTIDE_ALLOW_DATABASE_INITIALIZATION
```

4. 启动服务。

```powershell
mise exec -- npm start
```

5. 浏览器访问 `http://127.0.0.1:18092/console/`。开发界面另开 `mise exec -- npm run dev:console`，它只在 `127.0.0.1:5173` 提供页面，并把 `/v1` 转到 `18092`。

6. 停止时向该进程发送 Ctrl+C 或 `SIGTERM`。不要另起一个进程去“顶替”仍持有数据库锁的旧进程。

需要解析器时，在启动前同时设置 Java 17 可执行文件、classpath JSON 数组、插件名和私有临时目录。四项缺一不可；全空则不启动 Java。生产入口不读取测试用的 manifest。

## 配置

| 启动代码中的固定值 | 含义 |
| --- | --- |
| 连接池 `max: 16` | 不是环境变量 |
| `connectionTimeoutMillis: 5000` | 连库超时 |
| `statement_timeout: 15000` | 单条语句超时 |
| `application_name` | `sparktide-node-control` |
| 控制台目录 | 未设置 `SPARKTIDE_NODE_CONSOLE_DIR` 时使用构建产物旁的 `console` 目录 |
| 请求头上限 | 64KiB |
| 请求超时 / 头超时 | 30 秒 / 10 秒 |
| 全局在途上限 | 32。同一身份并发超过 8 返回 429 |

`SPARKTIDE_NODE_BIND` 只接受 `127.0.0.1`、`0.0.0.0`、`::1`、`::`。对公网或多网卡监听前，先完成 [网络与认证](./网络与认证.md) 的来源限制。

PDF 字体是可选的绝对或进程可读路径：设置 `SPARKTIDE_REPORT_FONT_FILE` 后，根智能体才会注册 PDF 工具。未设置时聊天仍可运行，只是没有该工具。

## 结果

- 初始化成功打印 `Journal, control, governance and execution schemas initialized`。
- 启动成功打印 `SparkTide listening on port` 和实际端口。打印内容不含数据库口令。
- 缺少 `SPARKTIDE_NODE_DATABASE_URL` 时立即失败，文案说明没有内存库。
- 执行库不是 21 时失败，文案要求先显式运行 `db:initialize`。
- 初始化开关不是 `true` 时，命令失败且声明不能隐式改已有库。
