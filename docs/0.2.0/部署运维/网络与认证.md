# 网络与认证

管理接口和业务接口各自认证。浏览器控制台只保存内存中的 Bearer 令牌。出站调用另有 origin 白名单，通过注册 JSON 校验不等于允许访问该主机。


## 范围

变量的类型和缺省见 [环境变量](./环境变量.md)。控制台登录见 [应用与授权](../控制台操作/应用与授权.md)。

## 步骤

1. 独立进程保持默认绑定 `127.0.0.1`。容器使用编排自带的宿主回环映射，不要再把 `18092` 发布到 `0.0.0.0`。
2. 设置 `SPARKTIDE_ADMIN_TOKEN`。用它登录控制台的平台管理员。不要把该值同时登记进 `SPARKTIDE_SECRET_NAMES`。
3. 若使用企业身份，同时设置发行者、JWKS URI 和受众。联邦令牌的角色只能是 `USER` 或 `APP_ADMIN`，算法固定为 RS256。平台管理员仍走管理令牌，不从 OIDC 令牌提升。
4. 列出模型、工具、远程知识和嵌入服务的精确 origin，填入 `SPARKTIDE_ALLOWED_ORIGINS`。生产保持 `SPARKTIDE_ALLOW_HTTP` 不为 `true`。
5. 为每个 `secretRef` 准备同名环境变量，并写上 origin 和应用绑定。
6. 从控制台或业务客户端发送 `Authorization: Bearer <由身份源签发的令牌>`。不要把令牌放进查询串。
7. 业务回调需要的私有认证材料由受信边界注入。控制台和模型请求都不能携带或伪造这份材料。

本机开发若必须使用 HTTP 身份源，仅对 `127.0.0.1`、`localhost` 或 `[::1]` 设置 `SPARKTIDE_OIDC_ALLOW_LOCAL_HTTP=true`。这不授权任意内网 HTTP。

## 配置

| 行为 | 当前实现 |
| --- | --- |
| 控制台认证 | 无 Cookie 会话。`fetch` 使用 `credentials: 'omit'` |
| CORS | 不提供开放 CORS。开发代理只转发到 `127.0.0.1:18092` |
| 转发头 | 缺省不信任 `Forwarded-For` 或 `Origin` 来构造身份 |
| 认证失败 | 同一来源失败过多返回 429，并带 `Retry-After`。成功认证后才进入业务限流 |
| 匿名健康检查 | `GET /actuator/health` 与 `GET /actuator/health/readiness` 不要求令牌，但会查库和执行器 |
| 请求容量 | 全局在途 32；同一主体并发 8。长连接的预览和可靠事件各占一条 |
| 出站端点 | 无用户名、密码、查询串和片段。主机不能依赖地址归一化。端口不能是 0 |
| 白名单 | 必须是 origin 本身，不能是带路径的完整 URL |
| 业务 secret | 解析发生在出站时，读取的是进程环境，不是控制台提交的 JSON |

当前 HTTP 入口没有注册 `/actuator/health/liveness`。开发运行说明里的“存活检查”不能当成一条已存在的路径。现有的 `/actuator/health` 与 `/readiness` 执行同一套数据库和执行器检查。

在反向代理后终止 TLS 时，仍要保证浏览器只访问受控入口，并且代理不会把使用者提交的令牌写进访问日志。平台进程本身不提供证书配置项。

## 结果

- 令牌错误返回未认证，响应不包含令牌原文。
- 角色不足返回 403。平台管理员访问业务会话、业务评测结果或运行时序会被拒绝或按钮不可用。
- origin 不在白名单时，工具和模型不会发出请求。
- 凭证撤销和委托过期在后续请求生效。活动运行上的委托续接仍要求同主体、同签发者和有效策略；最初授权被撤销后，执行继续被阻断。
- 刷新页面会丢失控制台令牌。服务端已受理的运行保持原状态，直到显式取消或自然结束。
