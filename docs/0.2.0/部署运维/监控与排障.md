# 监控与排障

可观测数据来自 PostgreSQL 的运行、模型事实和公共事件。当前没有 OTLP 导出，也没有自动告警外发。健康检查失败要先看结构和单活锁，而不是把副本数加一。


## 范围

控制台按钮见 [用量与诊断](../控制台操作/用量与诊断.md)。升级和备份见 [升级与恢复](./升级与恢复.md)。

## 步骤

1. 在服务器本机请求就绪检查。容器健康脚本访问的是容器内的 `127.0.0.1` 与 `SPARKTIDE_NODE_PORT`。

```powershell
Invoke-RestMethod http://127.0.0.1:18092/actuator/health/readiness
```

期望 JSON 为 `status=UP`、`implementation=nodejs`。不要把 `DOWN` 或连接失败解释成业务权限问题。

2. 若进程没有监听，查看启动日志里的变量名。常见失败是缺少数据库连接串、执行库不是 21、控制台目录不存在、OIDC 三项不完整，或 keyring 无法解码。
3. 若日志含 `Another Node executor owns this database`，说明该库已有执行器。先确认旧进程，不要再启动第二个。
4. 若就绪曾经为 `UP` 后又变成 503，且业务错误码为 `EXECUTION_OWNERSHIP_LOST`，表示持锁连接已断开。执行器不会自动重连去抢锁。恢复时先确认旧连接已经释放。
5. 对单个运行，用所有者身份在控制台读取事件和模型账本。平台管理员不要用「读取运行时序」旁路业务正文；该按钮对管理员是禁用的。
6. 需要告警时，在「运维与评测 / 告警」点「显式评估规则」，再确认或标记恢复。状态变更不会发出 Webhook。
7. 停止接收新流量后，向进程发送 `SIGTERM` 或 Ctrl+C，等待最多约 30 秒的编排宽限。不要删除会话、事件、审批或账本来“修好”未知结果。

容器日志驱动是 `json-file`，单文件 50MB，保留 5 个。这只覆盖容器标准输出，不是审计导出，也不是数据库备份。

## 配置

| 现象 | 含义 | 下一步 |
| --- | --- | --- |
| 就绪 503，正文 `status=DOWN` | 日志库或控制库不是 1、注册表条件不满足，或 `execution.ready()` 失败 | 先核对是否做过显式初始化，以及锁是否仍在 |
| 启动即退出并要求 `db:initialize` | `st_node_execution_meta.version` 不是 21 | 按 [升级与恢复](./升级与恢复.md) 在目标库初始化。不要手改版本号 |
| 上传 503 `CAPABILITY_UNAVAILABLE` | 解析器四项未配置，或默认 `runtime` 镜像 | 改用 `runtime-parser` 或配齐四项后重启。不要用空解析结果冒充成功 |
| 模型调用 503，文案要求受支持的供应商 | 发布计划里没有可用模型 | 发布供应商、模型和档案，并检查 origin 白名单 |
| 429 与 `Retry-After` | 认证失败过多、主体请求过多，或并发达到 8 | 等待后重试读取。写操作仍用原幂等键核对，不换键重放 |
| 工具 `UNKNOWN` | 派发后没有可靠终态，或重启时收口 | 到业务系统按原调用核对。平台不会自动再调用 |
| 预算 `UNKNOWN` | 供应商用量不完整或提交结果未知 | 保持占用。人工处理分成模型证据和合成探测预算两条入口 |
| 告警页无外发记录 | `notificationDelivery=DISABLED`，`autoEvaluate=false` | 这是当前配置，不是投递成功 0 次 |
| 可观测里的 OTLP | 固定 `NOT_CONFIGURED` | 不要接一套未装配的采集器并写成已支持 |
| `/actuator/health/liveness` 404 | 当前服务器没有这条路由 | 使用 `/actuator/health` 或 `/actuator/health/readiness` |

`HTTP_REJECTION` 告警信号为 `UNAVAILABLE`。规则编辑器写明：该信号未接通时失败关闭。不要启用一条永远没有数据源的拒绝率规则来代表网关状态。

预览流断开、控制台刷新和导出失败都不会取消运行。取消只来自「停止运行」、队列的「确认停止」，或进程关闭时对活动执行的中止。

## 结果

- 健康响应不含令牌、连接串和业务正文。
- 控制台「读取应用统计」的时间窗口是 1 到 168 小时，统计口径是数据库事实，不是采样 Span。
- 进程关闭若不能可靠结束评测和执行器，退出码会被设为失败。此时先看数据库里的运行终态，再决定是否启动新进程。
- 排障结束的标准是：就绪为 `UP`，单活锁只属于预期进程，未知事实仍保持未知，并且没有新增第二个执行器。
