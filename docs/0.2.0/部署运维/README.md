# 部署运维

启澜 `0.2.0` 以单个 Node 进程加 PostgreSQL 运行。初始化、启动、备份和切换都是针对明确目标的单独操作；把命令写在本文里不等于已经执行。


## 范围

本栏目给出可运行的准备、容器、独立进程、环境变量、认证、升级和排障步骤。产品能力见 [能力指南](../能力指南/README.md)，控制台见 [控制台操作](../控制台操作/README.md)。

当前部署不包含：多活集群、运行时 Redis、自动建表、默认口令、OTLP 导出，以及默认镜像中的 Java 解析器。

## 阅读顺序

1. [部署准备](./部署准备.md)：版本、端口、单活和显式初始化。
2. [环境变量](./环境变量.md)：从进程加载代码整理的全部变量。
3. [Docker部署](./Docker部署.md) 或 [独立进程部署](./独立进程部署.md)。
4. [网络与认证](./网络与认证.md)。
5. [升级与恢复](./升级与恢复.md)、[监控与排障](./监控与排障.md)。

## 步骤

1. 选定一个空闲的 PostgreSQL 17 数据库，并确认操作者有权在维护窗口里安装平台表。
2. 在当前进程注入连接串和管理令牌。使用 `Read-Host` 或密钥管理系统，不要把口令写进仓库、命令历史或本文。
3. 构建 `0.2.0`。需要解析上传文件时再选择带解析器的镜像或本机 Java 17。
4. 只在确认目标库之后，临时打开初始化开关并执行初始化命令。完成后立刻删掉该开关。
5. 启动唯一的服务进程，检查就绪响应的 `implementation` 是否为 `nodejs`。
6. 用浏览器打开 `/console/`，使用刚注入的管理令牌登录，再按 [应用与授权](../控制台操作/应用与授权.md) 创建应用。

## 配置

| 项目 | 当前默认 |
| --- | --- |
| 产品版本 | `0.2.0` |
| 运行时 | Node `24.22.1`，npm `10.9.4` |
| 数据 | PostgreSQL 是唯一可靠真源。服务启动只检查结构 |
| 执行库 | 初始化后为 21。日志库、控制库、注册表元数据为 1 |
| 监听 | 独立进程默认 `127.0.0.1:18092`。容器内是 `0.0.0.0:18092`，宿主端口只发布到回环 |
| 控制台 | 默认同源启用。静态资源缺失时启动失败 |
| 单活锁 | 顾问锁 `1937006964, 3`。第二个执行器不能共享同一库 |

服务不读取 `.env`。连接池大小、语句超时写在启动代码里，不能靠未文档化的环境变量修改。

## 结果

- 未设置 `SPARKTIDE_ALLOW_DATABASE_INITIALIZATION=true` 时，初始化命令失败且不改表。
- 就绪为 `UP` 只说明结构、注册表条件和执行器锁可用。它不证明模型厂商、身份源或解析器可用。
- 停止进程会处理 `SIGINT` / `SIGTERM`，先停执行器再归还连接池。已受理任务不会因为文档被阅读而继续或取消。
