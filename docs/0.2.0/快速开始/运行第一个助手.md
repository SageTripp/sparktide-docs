# 运行第一个助手

目标是得到一个能发送消息、连续追问并恢复历史的业务聊天页面。先只接入一个模型和一个智能体，完成后再增加工具、知识和自定义组件。

## 1. 准备平台

按照[部署准备](../部署运维/部署准备.md)确认运行依赖，选择[Docker 部署](../部署运维/Docker部署.md)或[独立进程部署](../部署运维/独立进程部署.md)。数据库初始化必须指向确认过的目标；不要使用现有业务数据库做临时验证。

默认本地端口为 `18092`。启动后检查：

```powershell
Invoke-RestMethod http://127.0.0.1:18092/actuator/health/readiness
```

`/actuator/health` 与 `/actuator/health/readiness` 都检查数据库格式与执行器；当前没有单独的 liveness 路径。模型、业务权限和工具回调仍需后续验证。

## 2. 准备应用和后台

1. 在[控制台](../控制台操作/README.md)使用管理身份连接平台。
2. 按[应用与授权](../控制台操作/应用与授权.md)建立业务应用并准备后台所需凭据。
3. 按[后端接入](../开发接入/后端接入.md)选择与 Java / Spring Boot 版本匹配的 Starter。
4. 声明一个模型提供商、模型和智能体；配置平台地址、应用、回调地址与模型凭据。
5. 按[身份与权限](../开发接入/身份与权限.md)接入已有登录，再按实际配置发布或校验资源。

使用真实可访问的模型服务；本地业务回调和模型地址需要符合平台出站白名单。不要把开发身份直接带到生产。

## 3. 接入前端

按[前端接入](../开发接入/前端接入.md)安装配套 SDK 和 UI 包，用 `createClient` 连接业务后台，选择 React、Vue 3 或 Vue 2 的面板。现有 Cookie 或认证头通过 `auth` 配置，智能体名称应与后台声明一致。

可组合的后台声明、配置与前端示例见[完整示例](../开发接入/完整示例.md)。

## 4. 验证一个完整会话

| 操作 | 应观察到的结果 |
| --- | --- |
| 发送“你好，介绍一下你能做什么” | 请求受理，显示回答，运行进入终态 |
| 在同一会话追问 | 保持同一会话，并关联前文 |
| 刷新页面后打开历史 | 已保存消息仍可读取，不重新调用模型 |
| 在运行中点击停止 | 发出显式取消请求，界面显示实际结果 |
| 退出登录并换用户 | 旧身份的会话和内容不继续展示 |

网络断开或关闭页面不等于取消后台运行。暂时显示的流式尾部也不等于可靠保存；恢复以服务端可靠历史为准。

## 5. 出错时按链路定位

- 页面无法连接：先检查业务后台地址、代理与跨域配置。
- 401 / 403：检查业务登录和当前主体权限，不通过增加 `context` 字段绕过。
- 智能体无法解析：检查声明、发布状态和名称；不回退到任意默认版本。
- 模型或工具失败：在运行记录中查看实际错误及回调连通性。

详细处理见[监控与排障](../部署运维/监控与排障.md)。完成后可继续接入[业务工具](../能力指南/业务工具.md)或[知识问答](../能力指南/知识问答.md)。
