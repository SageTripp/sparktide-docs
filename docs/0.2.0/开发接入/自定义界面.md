# 自定义界面

根 SDK 不渲染界面。视觉来自 `@sparktide/ui-basic` 或 `@sparktide/ui-dashboard` 的框架子路径，外加该包的 `style.css`。两个库导出同名部件，根节点分别带 `data-st-library="basic"` 和 `data-st-library="dashboard"`。一个聊天区域选用其中一个库。

部件和状态的接法见 [前端接入](./前端接入.md)。本章只处理布局、主题和业务卡片。

## 可组合部件

三个框架子路径都导出这些名字：`ChatPanel`、`Panel`（与 `ChatPanel` 相同）、`ChatSurface`、`ConversationList`、`MessageList`、`ChatInput`、`ApprovalList`、`CitationPreview`、`ChatError`、`RunStatus`、`FollowUpList`、`SummaryPanel`、`ChatTheme`、`ThemePortal`。

`ChatSurface`、列表、审批、错误和跟进列表需要已经存在的 `state` 与 `actions`。React 把 `useChat` 的返回值同时当作状态和动作。Vue 3 使用 `chat.state` 与 `chat`。Vue 2 mixin 使用 `chatState` 与 `chat`。`MessageList` 接收 `messages` 和 `onCitation`，不要求整份会话状态。`ChatInput` 接收 `chat`，或接收成对的 `state` / `actions`。

`SummaryPanel` 展示状态里的摘要，打开面板本身不调用模型。生成摘要走 `chat.generateSummary()`。`FollowUpList` 编辑、重排和移除未认领的排队输入，不代替审批。`ApprovalList` 的通过和拒绝才是工具确认。

服务端渲染期间 Provider 和面板不发请求。Vue 2 在 `mounted` 时 `start`，销毁时释放本地观察。

## 主题和文案

`ChatPanel` 以及 `ViewOptions` 上常用的显示属性：

| 属性 | 作用 |
| --- | --- |
| `label` | 面板可访问名称，默认「启澜」 |
| `welcomeTitle` / `welcomeDescription` | 空会话欢迎区 |
| `suggestions` | 宿主给出的建议问题，点击后明确发送，挂载时不调用模型 |
| `assistantLabel` | 欢迎页上的助手名，消息正文不重复署名 |
| `workspaceLabel` / `description` | 工作区显示名和品牌下方说明，不表示权限 |
| `appearance` | `native`、`light`、`dark`。`native` 使用该库默认明暗 |
| `density` | `comfortable`（默认）或 `compact` |
| `theme` | 根上的语义变量，键形如 `` `--st-primary` ``。十六进制主色会计算可读前景，显式前景优先 |
| `className` / `classNames` / `styles` | 根类名，或按部件名追加类和样式。局部 `styles` 优先于主题 |
| `defaultNavigationOpen` | 宽容器是否一开始展开会话导航，默认展开。窄容器先收起 |
| `messageNavigation` | 消息左侧定位，默认开启；至少两条用户消息且聊天区宽于 620px 时显示 |
| `renderText` | 可选的业务文本渲染。默认对普通文本转义。引用动作仍走当前工作台 |

`ChatTheme` 给自定义布局套上同一套实例主题。`ThemePortal` 默认留在当前根内；浮层挂到别的 DOM 根时传入同一个 `target`，并带上相同的 `theme` 和 `className`。

高度和内容宽度用主题变量 `--st-height`、`--st-content-max-width` 交给宿主。不要为了改间距去复制整份布局。

## 业务展示组件

卡片分两段：后台用 `@RenderWith` 声明工具成功结果对应的组件标识和版本；前端用 `defineAiComponent` 声明属性契约和 Renderer，并在创建聊天前 `registerComponents`。浏览器里的注册只决定当前页面能渲染什么，不向平台发布组件。

后台：

::: code-group

```java [Java]
@Tool(name = "equipment-status", description = "查询机组当前状态，只读")
@RenderWith(value = "equipment.status", version = "1.0.0", fallback = "请查看文字结果。")
public Output execute(Input input, ToolContext context) {
    return equipmentService.status(input.equipmentId());
}
```

```kotlin [Kotlin]
@Tool(name = "equipment-status", description = "查询机组当前状态，只读")
@RenderWith(value = "equipment.status", version = "1.0.0", fallback = "请查看文字结果。")
fun execute(input: Input, context: ToolContext): Output =
    equipmentService.status(input.equipmentId)
```

:::

`fallback` 在组件不可用、校验失败或渲染异常时显示。默认文案是「请查看文字结果。」。`@Agent(autoSelectUi = true)` 才会选用自动导入的 UI 合同目录，而且目录必须存在。常规接入保持默认 `false`，由前端注册精确组件。`commonComponents` 默认 `true` 时，允许客户端注册下一节的通用展示组件，不放宽工具权限。

前端在发消息之前注册，单客户端最多 64 个不同的 `id@version`：

::: code-group

```tsx [React]
import {createClient, defineAiComponent, s} from '@sparktide/frontend-sdk';

const equipmentStatus = defineAiComponent({
  name: 'equipment.status',
  version: '1.0.0',
  description: '展示机组状态',
  fallback: '请查看文字结果。',
  props: s.object({
    equipmentId: s.string().min(1).max(64).describe('机组标识'),
    state: s.string().describe('当前状态'),
  }),
  render: (props) => (
    <p>{props.equipmentId}：{props.state}</p>
  ),
});

const ai = createClient({baseUrl: '/api/ai', auth});
ai.registerComponents([equipmentStatus]);
```

```ts [Vue 3]
import {defineComponent, h} from 'vue';
import {defineAiComponent, s} from '@sparktide/frontend-sdk';

export const equipmentStatus = defineAiComponent({
  name: 'equipment.status',
  version: '1.0.0',
  description: '展示机组状态',
  fallback: '请查看文字结果。',
  props: s.object({
    equipmentId: s.string().min(1).max(64).describe('机组标识'),
    state: s.string().describe('当前状态'),
  }),
  render: defineComponent({
    props: {equipmentId: String, state: String},
    setup(props) {
      return () => h('p', `${props.equipmentId}：${props.state}`);
    },
  }),
});
```

```ts [Vue 2]
import {defineAiComponent, s} from '@sparktide/frontend-sdk';

export const equipmentStatus = defineAiComponent({
  name: 'equipment.status',
  version: '1.0.0',
  description: '展示机组状态',
  fallback: '请查看文字结果。',
  props: s.object({
    equipmentId: s.string().min(1).max(64).describe('机组标识'),
    state: s.string().describe('当前状态'),
  }),
  render(props: {equipmentId: string; state: string}) {
    return props.equipmentId + '：' + props.state;
  },
});
```

:::

`s.object` 生成闭合对象：未声明的属性会被拒绝，缺省字段使用 `.optional()`。数组用 `s.array`，元素不能再标 optional。`name` 可以带命名空间；不含点且不超过 64 时，资源 `id` 等于 `name`。带点的名字会收成稳定的 `ns-` 前缀标识。`@RenderWith` 的标识要和这里的 `id` 一致，版本与 `version` 一致。

`interaction: 'FORM'` 或 `'QUESTION'` 表示服务端会持久等待用户回答。省略时只展示。`modelBinding: false` 的合同只渲染历史，不放进发给模型的 `uiCapabilities`。`exportComponentCatalog` 产出目录 JSON 和契约哈希，供后台构建核对；浏览器拿着这份 JSON 不能发布组件。

注册表校验失败会抛错。面板在单个组件渲染失败时隔离错误并显示 `fallback`。

## 可选通用组件包

`@sparktide/ai-components@0.2.0` 提供四份 `3.0.0` 合同：`common.genui`、`common.genui-form`、`common.genui-question`、`common.genui-icons`。前三个默认注册，图标需要显式列入 `include`。属性是对象 `spec`，由生成的 Schema 校验。旧的 `2.0.x` 合同只用于按精确版本渲染历史，不再绑定给模型。地图不在这个包里，需要时用上一节自行注册。

它的 peer 精确依赖核心 `0.2.0`，安装方式与界面包相同，见 [接入总览](./接入总览.md)。引入样式 `@sparktide/ai-components/style.css`。引擎脚本默认从 `/genui-assets/` 按需加载，可用 `assetBase` 改位置。Vite 工程可以使用子路径 `@sparktide/ai-components/vite` 的 `genuiAssets()` 在开发和构建时托管这些文件。

::: code-group

```tsx [React]
import {CommonComponents} from '@sparktide/ai-components/react';
import '@sparktide/ai-components/style.css';

ai.registerComponents(CommonComponents, {
  include: ['genui', 'form', 'question'],
  appearance: 'auto',
  locale: 'zh',
  assetBase: '/genui-assets/',
});
```

```ts [Vue 3]
import {CommonComponents} from '@sparktide/ai-components/vue';
import '@sparktide/ai-components/style.css';

ai.registerComponents(CommonComponents, {
  include: ['genui', 'form', 'question'],
});
```

```ts [Vue 2]
import {CommonComponents} from '@sparktide/ai-components/vue2';
import '@sparktide/ai-components/style.css';

ai.registerComponents(CommonComponents, {
  include: ['genui', 'question'],
});
```

:::

`createCommonComponents(options)` 返回组件数组，便于和业务卡片拼在一起再注册。配置只留在浏览器。`onSubmit` 收到的调查答案仍是用户输入，由后端按原权限处理，不构成审批。无框架页面可以用包根导出的 `mountCommonComponent`，卸载时调用它返回的函数。

后台 `@Agent` 保持 `commonComponents = true`（默认）时，这些合同才允许出现在该智能体的界面能力里。设为 `false` 会关闭这组通用组件，不影响原有工具权限。

## 文件预览

平台保存的 PDF 用 `ai.artifacts.download` 或面板自己的下载。业务系统保存的文件只有元数据：`storage: 'business'`、`downloadUrl`、`previewUrl`。给 `createChat` / `useChat` 提供：

::: code-group

```ts [TypeScript]
ai.createChat({
  agent: 'main',
  onPreviewArtifact: async (preview) => {
    if (preview.artifact.storage === 'business') {
      openBusinessPreview(preview.artifact.previewUrl);
      return;
    }
    openPdfBlob(preview.blob);
  },
  onDownloadArtifact: (artifact) => downloadWithBusinessAuth(artifact.downloadUrl),
});
```

```js [JavaScript]
ai.createChat({
  agent: 'main',
  onPreviewArtifact: async (preview) => {
    if (preview.artifact.storage === 'business') {
      openBusinessPreview(preview.artifact.previewUrl);
      return;
    }
    openPdfBlob(preview.blob);
  },
  onDownloadArtifact: (artifact) => downloadWithBusinessAuth(artifact.downloadUrl),
});
```

:::

未配置 `onPreviewArtifact` 时，默认界面不显示业务文件的预览按钮。SDK 不会把登录头加到 `downloadUrl` 上。引用预览若是业务查询快照，用 `formatReferencePreview` 把它收成标题和正文；这个函数只影响展示，不会按它去请求业务地址。
