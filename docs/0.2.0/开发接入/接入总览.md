# 接入总览

常规接入分三段：平台保存会话和执行，业务后台用后端 SDK 暴露 `/api/ai` 并注册能力，业务页面用前端 SDK 携带现有登录。浏览器里的应用标识、模型参数和用户上下文都不是权限。

## 当前源码版本

下表是仓库里的版本字段。安装时使用同一套本地制品，坐标和包名必须与构建时的版本字符串一致。

| 部件 | 版本字段 | 位置 | 分发状态 |
| --- | --- | --- | --- |
| 平台 | `0.2.0` | 平台 `package.json` 的 `version`，`private: true` | 源码版本，本页不提供 npm 安装名 |
| 后端 SDK | 默认 `0.2.0` | 根 `build.gradle.kts` 的 `sdkVersion`，缺省 `0.2.0` | `publishToMavenLocal` 或已提供的同版本 Jar；未写入 Maven Central |
| 前端核心 | `0.2.0` | `@sparktide/frontend-sdk` | `private: true`，用源码 `npm pack` 或已提供的同版本 tarball |
| 基础界面 | `0.2.0` | `@sparktide/ui-basic`，peer 精确依赖核心 `0.2.0` | 与核心一起本地安装 |
| 大屏界面 | `0.2.0` | `@sparktide/ui-dashboard`，peer 同上 | 与核心一起本地安装 |
| 通用展示组件 | `0.2.0` | `@sparktide/ai-components`，peer 精确依赖核心 `0.2.0` | 可选；普通聊天面板不依赖它 |

覆盖后端版本时，构建命令带 `-PsdkVersion=<同一版本>`，业务工程里每个 `dev.sparktide` 模块都写这个字符串。默认命令使用 `0.2.0`。历史候选版本号只属于当时的本机验收，不能当成现在可以下载的公开发行号。

平台包声明的 Node 是 `24.22.1`。前端 SDK 的 `engines` 是 Node `>=22 <23`。构建后端 SDK 仓库使用随仓 Gradle Wrapper `8.14.4` 和 JDK 17；Java 8 字节码测试另需本机 JDK 8。

## 选择运行时

一个业务进程只选一套后端核心。

| 业务运行时 | 引入 | 说明 |
| --- | --- | --- |
| Java 17、Spring Boot 4、Jakarta | `sdk-spring-boot-starter` | Starter 按 Spring Boot `4.0.8` 编译，传递 `sdk-java` |
| Java 8、Spring Boot 2.6.6、javax | `sdk-spring-boot2-starter` | 传递 `sdk-java8`；Maven 旧 Boot BOM 把 `kotlin.version` 对齐为 `2.3.20` |
| 已有 Kotlin 协程封装 | 在对应核心之外再加 `sdk-kotlin` | 额外提供 DSL，不替换 Starter |
| 无 Spring、自行管理 HTTP | `sdk-java` 或 `sdk-java8` | 使用 `PlatformClient`；业务聊天路由仍建议由 Starter 提供 |

模型适配器按供应商单独引入，例如 `sdk-model-openai-compatible`、`sdk-model-openai`、`sdk-model-deepseek`、`sdk-model-ollama`、`sdk-model-opencode-go`。核心不强制带上全部供应商。每个坐标的用途和参数见 [SDK 依赖](../参考资料/SDK依赖/README.md)。

前端根包没有视觉。页面从 `@sparktide/ui-basic` 或 `@sparktide/ui-dashboard` 的 `/react`、`/vue`、`/vue2` 导入组件，并单独引入该包的 `style.css`。状态适配从 `@sparktide/frontend-sdk/react`、`/vue`、`/vue2` 导入。`/platform` 是运维客户端，业务聊天不使用它。

## 取得同版本制品

本页不给出 registry 安装命令。制品来自源码构建，或来自已经交给你的、版本字符串完全相同的 Jar / tarball。

### 后端：安装到本机 Maven 仓库

在后端 SDK 仓库根目录执行：

```powershell
.\gradlew.bat publishToMavenLocal
```

需要指定版本时：

```powershell
.\gradlew.bat publishToMavenLocal -PsdkVersion=0.2.0
```

业务工程打开 `mavenLocal()`，依赖写 `dev.sparktide:<模块>:<版本>`。模块名与 `settings.gradle.kts` 里的工程名一致，例如 `sdk-spring-boot-starter`。文档仓库 `examples/0.2.0/` 使用同样的 Maven 坐标，不使用 SDK 工程依赖。

### 前端：打本地 tarball

在前端 SDK 仓库根目录执行：

```powershell
npm ci
npm run build
npm pack
npm pack --workspaces
```

`npm pack` 打印实际文件名。按 npm 对作用域包的命名，`@` 去掉、`/` 换成 `-` 后接版本，对应文件是 `sparktide-frontend-sdk-0.2.0.tgz`、`sparktide-ui-basic-0.2.0.tgz`、`sparktide-ui-dashboard-0.2.0.tgz`。可选通用组件是 `sparktide-ai-components-0.2.0.tgz`。以命令输出的文件名为准。

把 tarball 放到业务工程可见的目录后安装。三个包管理器安装同一组文件：

::: code-group

```sh [npm]
npm install ./vendor/sparktide-frontend-sdk-0.2.0.tgz ./vendor/sparktide-ui-basic-0.2.0.tgz
```

```sh [pnpm]
pnpm add ./vendor/sparktide-frontend-sdk-0.2.0.tgz ./vendor/sparktide-ui-basic-0.2.0.tgz
```

```sh [Yarn]
yarn add ./vendor/sparktide-frontend-sdk-0.2.0.tgz ./vendor/sparktide-ui-basic-0.2.0.tgz
```

:::

大屏把 `ui-basic` 换成 `ui-dashboard`，版本仍是 `0.2.0`。核心、界面包和可选 `ai-components` 的 peer 必须同时是 `0.2.0`。现代打包器使用 `package.json` 的 `exports`。Webpack 4 一类传统解析器使用包根的 `main` / `module` / `types`，以及包内物理文件 `react.js`、`vue.js`、`vue2.js`、`style.css`；这些文件转发到构建后的 `dist`。宿主仍配置自己的 Babel 和 CSS loader。

## 建议顺序

1. 准备可访问的平台 `0.2.0`，并在平台登记应用。应用标识只划定范围。登记步骤见 [快速开始](../快速开始/README.md) 与 [部署运维](../部署运维/README.md)。
2. 按上一节取得后端制品，按 [后端接入](./后端接入.md) 声明 Provider、模型和智能体，配置平台地址、应用凭据和回调地址。
3. 按 [身份与权限](./身份与权限.md) 复用现有登录。多租户或自定义主体时提供 `BusinessPrincipalMapper`。
4. 开发环境把 `sparktide.deployment.mode` 设为 `DEVELOPMENT`，确认声明能发布。生产默认只核验已经发布的定义。
5. 按上一节取得前端制品，按 [前端接入](./前端接入.md) 把 `baseUrl` 指到业务后台的 `/api/ai`。
6. 需要拆布局或业务卡片时再读 [自定义界面](./自定义界面.md)。已有 HTTP 客户端时读 [HTTP 接入](./HTTP接入.md)。

## 当前边界

平台能力说明写明：会话包含排队跟进和同次运行引导、审批、摘要和归档；文件成果在配置中文字体并升级执行存储后可以生成 PDF；Word、Excel、PPT 不在本次实现。知识检索调试和知识评测的公共合同还在，服务端尚未提供，不能用空结果代替。默认单活，多副本不自动成为多实例执行。业务预算人工结算不会把未知用量改成 0。

前端跟进是否可发送，以运行中的 `GET /api/ai/follow-ups/capabilities` 为准。当前平台源码返回的模式是 `QUEUE` 与 `STEER`。能力端点缺少或 `modes` 为空时，前端关闭跟进，普通发送保持可用。

更完整的产品边界见 [能力指南](../能力指南/README.md)。源码结论写在平台 `docs/项目管理/能力边界.md`。
