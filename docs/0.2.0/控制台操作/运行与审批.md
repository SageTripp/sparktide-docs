# 运行与审批

「会话与运行」用应用身份创建会话、发送消息、停止运行和处理审批。事件栏来自 PostgreSQL 公共事件，不是采样 Trace，也不是完整的 DSH 私有日志。


## 范围

归档、恢复和重命名没有控制台按钮。跟进模式以服务端能力声明为准。协议边界见 [会话交互](../能力指南/会话交互.md)。

## 步骤

1. 打开 `#runs`。左侧点「刷新列表」，填写标题后点「创建」。创建结果未知时保留原键，先点「刷新列表核对」，再用原键重试或放弃原提交。
2. 选中会话后点「刷新会话」。在输入框写消息并点「发送」。发送是单次的；未知回执不会自动换一把新键。可用「使用原 key 重试」「刷新会话核对」或「放弃原提交」。
3. 需要停止时点「停止运行」。按钮在请求发出后显示「取消请求已发…」。退出登录或刷新不会代替这次取消。
4. 右侧点「刷新事件」。时间线只展示已落库公共事件，可改每页条数并翻页。若有实时回答，它是当前连接上的预览，刷新后以可靠事件为准。
5. 有待处理交互时，审批区显示工具、风险、审批标识、参数摘要和过期时间。未过期且标识完整时，点「同意并继续执行」或「拒绝操作」。
6. 问卷只渲染控制台认识的字段，提交按钮使用服务端给出的 `submitLabel`。不认识的结构会提示改到受支持的客户端，不会提交一段通用 JSON。
7. 在「后续输入」点「刷新状态」。有 `QUEUE` 时可排队；只有存在真实活动 Run 且能力含 `STEER` 时，才出现引导该 Run 的选项。然后点「提交后续输入」。
8. 可编辑的用户主消息显示「编辑此消息」。改完点「确认提交编辑」。这会创建新 Run，不回滚已执行副作用。
9. 「生成摘要」和「生成标题」是独立计量操作。进行中可点「继续查询」，最多短轮询约 60 秒，不会自动重新生成。手动改标题的入口当前没有。

平台管理员看到的说明是：请使用会话所有者的应用身份。组件不会用管理令牌读取业务队列。

## 配置

| 控件 | 限制 |
| --- | --- |
| 后续输入正文 | 1 到 16384 个字符 |
| 编辑正文 | 1 到 16384 个字符，且消息 `editable` 为真、角色为 user |
| `QUEUE` | 单选「QUEUE · 排队到当前队列」。受理不等于已经绑定 Run |
| `STEER` | 文案含真实 Run 标识。没有 `activeRunId` 时单选不可用 |
| 暂停队列 | 仅在未暂停时可点。只暂停后续派发 |
| 恢复队列 | 仅在已暂停时可点。若服务端要求新鲜业务认证，控制台不能补胶囊 |
| 停止队列 | 先点「停止队列」，再点「确认停止」。会请求取消活动 Run |
| 审批过期 | 过期后两个决定按钮不可用。缺少真实过期时间时也不能提交 |
| 事件原文 | 「原始 data」默认折叠。展开后仍是已保存的公共事件，不是预览尾部 |

列表上的「已归档」只表示服务端 `archivedAt` 有值。本页不能把会话归档或恢复。

## 结果

- 发送后的可靠增量出现在消息列表；结构化结果要等完整校验后才发布。
- 审批或问卷提交后，若服务端仍显示待处理，页面要求刷新核对，不重复提交。
- 412 表示队列或历史修订已变化，本地输入保留。
- 跟进状态为已受理、已应用、已拒绝或已取消。失败码包括运行失败、取消、超时，以及重启后未确认。
- 模型调用诊断折叠在会话页，标题写明是配置价目，不是供应商账单。明细见 [用量与诊断](./用量与诊断.md)。
