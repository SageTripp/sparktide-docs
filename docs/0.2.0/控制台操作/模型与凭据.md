# 模型与凭据

控制台可以登记模型资源、查看健康、编辑配额和追加人工证据。密钥值不进资源编辑框，也不进浏览器存储。


## 范围

本文覆盖资源页中的模型四类，以及概览上的健康、配额和账本入口。环境变量见 [环境变量](../部署运维/环境变量.md)。模型语义见 [模型](../能力指南/模型.md)。

## 步骤

1. 以管理者打开「资源」。用类型按钮切换「模型供应商」「模型」「模型绑定」「模型档案」。
2. 在创建区填写 `id`、`x.y.z` 和 JSON 对象，点「创建草稿」。本地提示上限为 128KiB，根必须是对象。这只是浏览器预检。
3. `secretRef` 只写运维已经登记的引用名。页面提示不会接收 secret 值或 token。
4. 选中草稿，修改定义后点「保存草稿」。有未保存改动时不能发布。确认后点「发布当前草稿」。发布后该版本正文不可修改。
5. 回到「概览」的「模型健康与探测」。点「刷新绑定」，选择一个已发布 `model-bindings`。未选择前不会批量读取健康。
6. 填写探测理由，按需勾选 `TOOL_CALLING`、`STREAMING`、`STRUCTURED_OUTPUT`，点「提交合成探测」。
7. 需要恢复被隔离的绑定时，填写重置理由、勾选确认，再点「重置管理隔离状态」。
8. 展开「配额配置、用量与预留」。先看服务端策略，再编辑 `policies` JSON 数组并「保存配额配置」。用量桶和预留要分别点页签才会读取。

`USER` 打开概览时不读取管理绑定。此时健康区不会列出真实绑定，空列表不能解释成「没有配置模型」。

编辑器里的 JSON 是定义对象，不是带 `id`、`version` 的信封。四类字段的类型、缺省和示例见 [模型](../能力指南/模型.md)。下面是一份可直接贴进「模型供应商」的定义；资源 id 填 `vendor-chat`，版本填 `1.0.0`。

```json
{
  "mode": "OPENAI_CHAT",
  "endpoint": "https://models.example.com/v1/chat/completions",
  "secretRef": "VENDOR_TOKEN",
  "stream": true
}
```

`secretRef` 只写已经在进程环境登记的名字，或 `vault:` 加凭据 id。不要把 token 本身贴进 JSON。全局目录的供应商和模型没有控制台应用切换，平台管理员使用不带应用段的 `/v1/model-providers` 与 `/v1/models`。业务应用里的绑定要引用它们时，把 `scope` 写成 `global`，并且创建该绑定草稿的人必须是平台管理员。

合成探测的「探测原因」必填，最长 512。`TEXT` 固定勾选且不能取消。另三个勾选的含义：

| 勾选 | 实际请求 | 何时勾选 |
| --- | --- | --- |
| `TOOL_CALLING` | 要求模型调用仅用于探测的 `health_echo`，参数为 `{ "value": "ok" }`。该工具不会在业务系统执行 | 模型声明了工具调用，且智能体要用工具、子智能体、界面或按需知识 |
| `STREAMING` | 要求至少一帧增量。`OPENAI_CHAT` 且供应商 `stream` 不是 `true` 时，这项直接记为 `UNSUPPORTED`，不会发出流式请求 | 供应商定义把 `stream` 设为 `true` |
| `STRUCTURED_OUTPUT` | 要求返回只含 `status: "ok"` 的 JSON 对象 | 档案使用了 `outputSchema` |

探测会产生真实调用和预算占用。输出 token 上限是模型 `capabilities.maxOutputTokens` 与 32 的较小值；模型没声明时用 32。结果未知时点「显式刷新」，不要再次提交同一探测。

配额编辑区只接受 `policies` 数组，不要包上 `appId` 或身份字段。空数组 `[]` 是合法配置，保存不会自动补策略。每条策略最多 64 条且 `id` 不重复。`id` 使用资源 id 规则。`scope` 为 `APP`、`TENANT`、`USER` 或 `MODEL`。`period` 为 `MINUTE`、`HOUR`、`DAY`、`MONTH`，窗口按 UTC 计算。`enabled` 省略表示生效，只有 `false` 会跳过。

至少写一个上限：`maxConcurrentRuns`、`maxRunRequests`、`maxConcurrentModels`、`maxModelRequests`、`maxTokens` 是 0 到 1000000000000 的整数。`MODEL` 范围不能写前两个 Run 准入字段。`value` 省略时按 `*`。`APP` 的 `value` 必须是 `*`。`MODEL` 的 `value` 可以是 `*`，或 `应用id/models/模型id@版本`。

金额上限用 `maxAmount` 加 `currency`。`maxAmount` 是十进制字符串，`currency` 是三位大写字母。带金额上限时，若写 `unknownPriceMode`，只能是 `REJECT`。没有金额、又要把未知价格单独计数时，写 `unknownPriceMode: "SEPARATE"`，并同时写整数 `maxUnpricedRequests`。

```json
[
  {
    "id": "app-day-tokens",
    "scope": "APP",
    "value": "*",
    "period": "DAY",
    "maxTokens": 200000,
    "unknownPriceMode": "SEPARATE",
    "maxUnpricedRequests": 20
  }
]
```

保存时还要另填变更原因。原因不写进这条 JSON。

## 配置

| 操作 | 条件 | 不会发生的事 |
| --- | --- | --- |
| 保存配额 | 管理者，且本地 JSON 通过预检 | 不把未知用量显示成 0 |
| 只读刷新核对 | 保存被阻断之后 | 不自动覆盖服务器，也不自动重放保存 |
| 登记模型人工对账 | 调用 `sendState` 为 `SENT`，并勾选确认 | 不修改物理回执和财务预留 |
| 修正合成探测预算 | 预留 `purpose` 为 `SYNTHETIC_PROBE`，并勾选确认 | 不接受业务预留，不改探测回执和健康结论 |
| 托管密钥 | 进程环境中的 keyring 与 active key | 控制台没有密钥编辑器。空 keyring 时凭据库返回 503 `CREDENTIAL_STORE_DISABLED` |
| 错误的复数变量 | `SPARKTIDE_CREDENTIALS_KEYRING` 或 `SPARKTIDE_CREDENTIALS_ACTIVE_KEY` | 进程拒绝启动，不会静默关闭加密 |

探测历史每页 20 条，用「上一页」「下一页」移动。结果未知时先点「显式刷新」，不要再次提交同一探测。

## 结果

- 草稿保存提示为「草稿已保存；本页未自动发布。」
- 发布提示为「已发布当前草稿。」
- 412 保留本地草稿和 revision，并要求先「刷新核对」。
- 健康区写明：初始 `CLOSED` 不是厂商可用性证明，合成探测也不是供应商账单。
- 配额预留表可以选择合成探测行，再进入预算修正。普通模型账本在会话页，见 [用量与诊断](./用量与诊断.md)。
