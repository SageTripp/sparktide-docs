# 用量与诊断

用量、审计和运维页读取 PostgreSQL 中的运行、模型事实和公共事件。未配置的外发不会显示成 0 次成功通知。


## 范围

本文包括概览指标、模型账本、审计、可观测、智能体评测、告警、脱敏和留存。知识检索评测不在「评测」页签里。

## 步骤

1. 管理者打开「概览」，点「显式刷新」。查看运行总数、按状态计数、未知费用运行和配置价目。不同币种分行显示，不能相加。
2. 在会话页展开「模型调用诊断」。点「刷新列表」，每页翻阅调用，再打开封闭字段明细和对账历史。需要时按 [模型与凭据](./模型与凭据.md) 的规则登记人工证据。
3. 打开「审计」。可填操作类型、操作主体、运行 ID，点「查询审计」。每页 50 条，点「读取同一快照下一页」才继续。导出按钮是「导出筛选首批（最多 50 条）」，文件含快照和续页游标，不是全量历史。
4. 打开「运维与评测」。默认在「可观测」。填写 1 到 168 的小时窗口，点「读取应用统计」。平台管理员可另点「读取平台状态」。
5. 时序区填写 Run 标识后点「读取运行时序」。该按钮在平台管理员身份上是禁用的，因为管理身份不能旁路读取业务运行正文；时序也只含事件名和可靠序号。
6. 「评测」由应用管理员维护数据集、质量门和真实运行。点「启动评测」前要确认会调用模型并产生费用。平台管理员不能代启动或读取业务评测结果。
7. 「告警」可编辑规则、点「显式评估规则」、按 `FIRING` / `ACKNOWLEDGED` / `RESOLVED` 翻页，再「确认告警」或「标记恢复」。删除规则会先读取真实 revision。
8. 平台管理员打开「脱敏策略」和「留存与归档」。留存先「只预览，不删除」，确认备份后再「按已启用策略实际清理」。

## 配置

| 页面事实 | 当前固定行为 |
| --- | --- |
| 可观测 | 响应标明不采样。`otlp` 为 `NOT_CONFIGURED`。缺失的 HTTP 拒绝计数不能当成 0 |
| 告警状态 | `webhookConfigured` 为假，`notificationDelivery` 为 `DISABLED`，`autoEvaluate` 为假。`HTTP_REJECTION` 信号为 `UNAVAILABLE` |
| 告警规则模板 | 新建模板默认 `enabled: false`。启用后仍只在显式评估时测量 PostgreSQL 事实 |
| 质量门 | `evaluationGate.enabled` 默认关闭。开启后，切换入口要求目标智能体精确版本已有当前数据集的全通过评测 |
| 评测分页 | 每页 20 条。人工评分不替代规则结果 |
| 留存自动清理 | 策略里把 `autoSweep.enabled` 设为真会被服务端拒绝。状态为 `automaticCleanup: NOT_CONFIGURED` |
| 可清理类别 | 仅 `ALERTS_RESOLVED`、`AUDIT`、`ARCHIVES`。`RUN_EVENTS`、`RUN_CONFIRMATIONS`、`ALERT_DELIVERIES` 不能打开清理 |
| metadata 归档 | 只为超过 168 小时的终态运行保存元数据快照，每批最多 100 个。不迁走事件，不是数据库备份 |
| 脱敏 | 正则在独立 Worker 中执行，限制 500 毫秒、32MiB、最多 2 个活动任务。失败不回退原文。只影响审计和归档导出 |

普通留存页没有审计专项留存的预览或执行按钮。合同中的 `previewAuditRetention` 与 `applyAuditRetention` 当前未注册到留存路由。

## 结果

- 概览没有运行时，状态表显示「暂无运行状态记录」，而不是补 0 元。
- 审计证据可展开查看运行、Trace、摘要和修订等已返回字段。导出失败时先查 `audit.export` 记录，页面不自动重试。
- 告警「确认」和「标记恢复」都要求理由和已确认的 revision。删除规则不删除历史告警。
- 留存清理不能撤销。可靠 Run、DSH session、公共事件、确认和模型调用事实不会通过这个入口删除。
- 「读取脱敏归档导出」只返回已做脱敏的 metadata 快照。没有 RAW 导出旁路。
